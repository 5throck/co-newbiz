5장 관리자·운영 가이드

이 챕터는 시스템 관리자(admin)와 운영자(dba·sre·release-engineer)를 위한 요약입니다. 상세 절차는 docs/manuals/admin-manual_ko.md와 docs/manuals/operations-manual_ko.md가 원본입니다.

계정 관리

관리자 콘솔에서 사용자를 생성하면 임시 비밀번호가 발급되고, 해당 사용자는 첫 로그인 시 비밀번호 변경을 강제받습니다(must-change-password).

# 임시 비밀번호 발급 (admin 전용)
curl -X POST http://localhost:8787/api/auth/password-reset \
  -H "Content-Type: application/json" -H "Cookie: $ADMIN_SESSION" \
  -d '{"userId": "<대상 ID>", "tempPassword": "<임시 비밀번호>"}'
  • 역할은 admin·analyst·viewer 3종입니다.
  • 사용자 삭제 시 password_history·session·api_token이 먼저 정리된 뒤 계정이 삭제됩니다.
  • 딜 데이터 접근은 ADR-0091에 따라 admin에게도 기본 비공개입니다 — admin이 딜을 보려면 명시적 멤버십이 필요합니다.

배포와 마이그레이션

  • db/migrations/의 마이그레이션은 번호 순서대로 1회만 적용됩니다. 순서 변경과 재적용은 금지입니다.
  • 배포 전 bun scripts/test-runner.ts unit과 bun scripts/audit.ts가 반드시 통과해야 합니다.
  • 롤백 절차는 docs/runbooks/deployment.md를 따릅니다.

백업·복구

SQLite(WAL 모드) 데이터베이스는 정기 백업 대상이며, 월간 복구 훈련으로 백업의 복원 가능성을 검증합니다. 백업이 있어도 복원 훈련이 없으면 백업은 증적일 뿐입니다. 절차는 docs/runbooks/backup-restore.md를 따릅니다.

모니터링·알림

  • 정기 수집 스케줄러의 실패는 알림 파이프라인을 통해 통보됩니다.
  • 데이터 신선도(data freshness)는 RAG 등급의 상한을 제한하므로, 수집 지연은 단순 운영 이슈가 아니라 평가 품질 이슈로 취급합니다.
  • 장애 발생 시 사후 분석(post-incident review) 문서를 남깁니다.

보안 기본 수칙

  • 시크릿·자격증명은 저장소에 커밋하지 않고, .env는 스테이징하지 않습니다.
  • 개인정보·MNPI 접근 권한은 역할 최소권한 원칙을 따릅니다.
  • 정기 취약점 스캔(security-scan) 결과에 대한 조치 상태를 추적합니다.
