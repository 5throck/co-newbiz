# Gate Agent Skill Output Description
1 Entity IC risk-officer rag-scoring-framework rag_assessment_proposed

AI-proposed RAG grade per docs/rag-framework.md — six dimensions, priority-ordered (not averaged), data confidence capping the ceiling. This is a PROPOSAL, never a decision.
2 Entity IC process-governance-manager rag-scoring-framework kill_criteria_check

Explicit pass/fail against every Kill Criteria condition applicable at this gate — see policies/group/neb-policy.md §4.
3 Entity IC brownfield-agent dd-to-valuation-bridge ic_memo

IC memo assembled per templates/deliverables/ic-memo-template.md — RAG table, DD findings, M&A special-topics section (BF only), Kill Criteria check, three-stage reviewer sign-off table.
4 Entity IC valuation-agent financing-plan-review financing_readiness_check

Financing PRECONDITION before the decision step — the IC package must contain the chk-financing evidence: executed commitment papers (equity commitment letter; debt commitment letter + fee letter + term sheet) or a documented internal-funds approval path, sources-and-uses, covenant headroom/leverage analysis, funds-flow memorandum draft, FX plan where currencies differ. No committed financing evidence = precondition FAIL, not a judgment call — a financing contingency weakens the bid and belongs to no reviewer's discretion.
4.5 Entity IC process-governance-manager insight-synthesis integrated_insight_review

Integrate market, financial, legal/regulatory and M&A special-topic outputs into a single strategic view with a mandatory cross-check, giving the human reviewer one coherent pre-IC package (graph-pilot wiring, backfill-report §4.1).
4.6 Entity IC docs-writer executive-presentation entity_ic_decision_deck

Build the Entity IC decision deck (Pyramid-Principle structure, one-page summary) from the integrated insight and valuation inputs (graph-pilot wiring).
5 Entity IC entity-ic-reviewer stage-gate-governance entity_ic_decision

Human reviewer confirms or corrects the AI-proposed RAG grade (with a reason if corrected — docs/manuals/business-manual.md §3) and records a decision: approved | rejected | conditional | withdrawn_pending_resubmission. The fourth state is not in the original design and was added per docs/pilots/pilot-003-doosan-bobcat-robotics.md finding F-2 — a real case (Doosan Bobcat/Robotics) withdrew and re-proposed with revised terms, a pattern the original three-state model could not represent. analysis_task.reviewed_by must be non-NULL on every required deliverable before this step can complete (design §8.9-1).
