# Pilot 013 — Hexapro / ETRI (R&BD, Brown Field Sub-Type — External Technology License-In)

**Case type**: R&BD (Brown Field sub-type, `case_subtype: rbd`, `rbd_source: external_technology_acquisition`) — the third real-case test of this field's enum, and the first that is **not** an internal-venture spin-off at all
**Region**: Korea (KR)
**Run mode**: Manual (no system — Stage 3/4 pilot per ADR-0034)
**Case source**: researched per user instruction (2026-08-20) to close the last untested `rbd_source` value
**Status**: In progress — public disclosure for this specific case is thinner than pilots 011/012, noted explicitly below rather than filled in

## 0. Purpose and Scope

Same public-data-only constraint as prior pilots. Pilots 011 (POSCO/Amberoad) and 012 (LG/Studio341) are both internal-venture spin-offs — real, but both instances of `rbd_source: internal_only` or `accelerator_partnered`. Neither tests the third value defined after pilot 012's finding F-2: `external_technology_acquisition` — a company licensing in technology it did not develop, from an external source (here, a government-funded research institute), with no spin-off or internal-venture structure at all. This pilot closes that gap, and separately captures a real government R&BD program's concrete parameters as calibration data.

## 3. Findings

| # | Finding | Type | Action |
|---|---|---|---|
| F-1 | For a research-institute (or other external, non-corporate) license-in R&BD deal, **TRL assessment (rbd-01) is materially harder to satisfy from public disclosure alone** than for an internal-venture spin-off — spin-off announcements typically come with track-record framing, license announcements typically don't. A real DD process (with actual document access) would not face this gap the way a public-data-only pilot does, but it confirms `rbd_source: external_technology_acquisition` deals should expect to lean more heavily on direct technical diligence with the licensor, not press disclosure. | Gap — informs DD emphasis, not a schema defect | Note in `checklists/rbd-technology-checklist.yaml`'s rbd-01 guidance that license-in deals should prioritize direct licensor technical documentation over public-source corroboration |
| F-2 | rbd-05's wording ("parent-entity relationship... equity retained, customer/supplier ties, brand association") is shaped for a spin-off's relationship to its originating company and doesn't cleanly fit a research-institute licensor relationship (royalty/follow-on-program continuity, not equity/brand). | Gap — checklist wording | Broaden rbd-05 to explicitly cover licensor relationships (ongoing royalty obligations, follow-on co-funding program eligibility) as an alternate shape to the spin-off parent-relationship pattern |
| F-3 | ETRI's real Technology Scale-up R&BD Program (KRW 360M/project, ≤12 months, ~10 projects/cycle, eligibility tied to a recent tech-transfer contract) is a concrete, real figure usable as calibration data for R&BD follow-on-funding sizing — the first pilot to supply a real per-project government R&BD funding amount. | Positive — real calibration data acquired | Note in `docs/governance/rag-framework.md` §6 or a future R&BD-specific calibration reference alongside pilot 012's 70% pivot-rate figure |
| F-4 | This pilot confirms `rbd_source: external_technology_acquisition` is a real, distinct case shape from both `internal_only` (pilot 011) and `accelerator_partnered` (pilot 012) — all three values in the field design (pilots 011/012's finding F-2) now have at least one real supporting case. | Positive — completes the three-value `rbd_source` enum's real-case validation | None needed |

## 4. Verdict

**Process partially executable, with real structural confirmation that `rbd_source: external_technology_acquisition` deals face a different public-data profile than spin-off deals** — weaker on TRL/track-record corroboration from public sources, but with real institutional-policy-level government-co-funding detail and a genuinely new, useful checklist wording gap (rbd-05). Not a failure under ADR-0034 — the reduced disclosure for this deal shape relative to the spin-off cases is itself the expected, informative finding, not a defect in the pilot or the checklist.
