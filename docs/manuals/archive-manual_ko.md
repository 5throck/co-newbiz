# 아카이브 매뉴얼 — 리드·애널리스트

> **언어**: **한국어** · [English](archive-manual.md)
> **대상**: 딜을 마감·보관·삭제 표시하거나 아카이브를 열람하는 딜 리드와
> 애널리스트. 시스템 관리자는 역할 분리에 따라 딜 내용을 볼 수 없으므로 이
> 매뉴얼의 대상이 아닙니다.

## 1. 딜의 네 가지 상태

| 상태 | 나타나는 화면 | 실행 주체 |
| --- | --- | --- |
| 진행 (open) | /projects, /pipeline, 모든 딜 화면 | — |
| 마감 (closed) | 아카이브 → 보관 프로젝트 | 리드 (종료/보관) |
| 보관 (archived) | 아카이브 → 보관 프로젝트 | 리드 (종료/보관) |
| 삭제 표시 (deleted) | 아카이브 → 삭제된 딜 | 리드(프로젝트) / analyst+(기회·마스터데이터) |

**삭제는 지우기가 아니라 표시입니다.** 삭제 표시된 딜은 기회·경로결정·대상
리스트·시너지 버전·사업성·게이트·리포트 행을 전부 유지합니다. 모든 목록이
표시를 필터링하기 때문에 활성 화면에서 사라질 뿐이며, 아카이브에서 감사용으로
그대로 열람됩니다.

## 2. 프로젝트 마감·보관하기

1. `/projects` → 행 액션 **종료/보관** (리드만).
2. 마감(closed) 또는 보관(archived)을 선택하고 **사유(필수)**를 입력합니다.
3. 프로젝트는 진행 목록에서 사라지고 아카이브 → 보관 프로젝트에 나타납니다.

보관된 프로젝트는 읽기 전용입니다. 멤버라면 개요와 분석 화면이 계속 열려
전체 기록을 점검할 수 있습니다.

## 3. 딜 삭제 표시하기

1. `/projects` → 행 액션 **삭제** (리드만). 한 번의 액션으로 프로젝트**와**
   source opportunity가 함께 표시되며, 파이프라인·진출방식 결정·기회 화면이
   자동으로 정리됩니다.
2. 확인창을 승인하면 manifest가 기록됩니다 — 누가, 언제, 당시 멤버가 누구였는지,
   그 딜이 근거로 삼은 시장분석 버전까지 함께입니다.
3. 미승격 기회는 `/opportunities` → 삭제. 승격된 기회는 반드시 프로젝트를
   먼저 삭제해야 합니다.

## 4. 아카이브 화면 사용법

`프로젝트 → 아카이브` (/projects/archives):

- **보관 프로젝트** — 상태 칩·종료일·사유와 함께 목록 표시. 개요 링크로
  원본 열람, 리드는 삭제(아카이브 → 삭제 표시로 라이프사이클 완결) 가능.
- **삭제된 딜** — 삭제자·시점·사유와 함께 표시. 원본 열람으로 보존 데이터를
  확인하고, 상세에서 manifest(시장분석 당시 버전 참조 포함)를 봅니다.

상세 열람마다 감사 로그가 기록됩니다. 열람 자격은 **마킹 시점 프로젝트
멤버**로서 영구적이며, 관리자는 딜 내용을 볼 수 없습니다.

## 5. 자주 묻는 질문

**Q. 삭제하면 데이터가 정말 지워지나요?** 아니요. 표시만 되고 원본은 전부
보존됩니다. 감사 시 아카이브에서 그대로 열람합니다.

**Q. 잘못 삭제했으면?** 삭제 표시 해제(un-delete)는 계획된 후속 과제입니다
(`docs/designs/2026-09-10-deletion-followups-plan.md` Workstream A). 그 전까지도
데이터가 보존되어 있으므로 감사 열람에는 지장이 없습니다.

**Q. 시너지 분석이 삭제 거부되는데?** 그 분석은 살아있는 딜의 전략적 근거입니다.
딜을 먼저 삭제 또는 보관한 뒤 시도하세요.

**Q. 시장분석이 갱신되면 아카이브도 바뀌나요?** 아니요. 보관/삭제 시점의
시장분석 버전이 manifest에 고정되어 당시 버전을 열람할 수 있습니다.
