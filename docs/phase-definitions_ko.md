# 페이즈 정의 (Phase Definitions)

이 문서는 모든 변형(variant)에서 사용되는 표준 워크플로 페이즈를 정의한다. 각 변형은 페이즈 1–5의 전문 에이전트를 커스터마이즈하며 전체 구조는 일관되게 유지된다.

## 페이즈 개요

| 페이즈 | 이름 | PM 역할 | 수행 주체 |
|-------|------|---------|----------|
| 0 | 프로젝트 시작 | 조율자(Orchestrator) | PM + 변형 셋업 에이전트 |
| 1 | 리서치 / 분석 | 관찰자(Observer) | 전문 에이전트 (변형별 정의) |
| 1-2 | 리서치 & 아키텍처 | 관찰자 / 게이트키퍼 | 전문 에이전트 (변형별 정의) |
| 2 | 설계 검토 & 승인 | 게이트키퍼(Gate Keeper) | PM + 시니어 전문 에이전트 |
| 3 | 실행 / 생성 | 조정자(Coordinator) | 전문 에이전트 (변형별 정의) |
| 4 | 전달 / 통합 | 조정자(Coordinator) | 전문 에이전트 (변형별 정의) |
| 5 | 라이프사이클 마무리 | 소유자(Owner) | PM (거버넌스 기록 갱신, 결정 로깅) |
| 6 | 품질 보증 & 최종화 | 소유자(Owner) | PM (감사 스크립트 실행, /sync, PR 생성) |

## 페이즈 상세

### 페이즈 0 — 프로젝트 시작
**PM이 페이즈를 연다**: 목표를 명확히 하고 범위를 확정하며 팀을 구성한다.
- PM이 요청을 검토하고 분류한다
- PM이 필요한 전문 에이전트를 식별한다
- 셋업 에이전트(있다면)가 환경을 준비한다
- **산출물**: 확정된 범위, 팀 배정

### 페이즈 1 — 리서치 / 분석
**PM은 관찰한다**: 전문가들이 자율적으로 작업한다.
- 리서치 에이전트가 데이터, 증거, 맥락을 수집한다
- 분석 에이전트가 발견을 종합한다
- PM은 품질 기준이 충족되지 않는 경우에만 개입한다
- **산출물**: 리서치 발견, 분석 보고서
- **게이트**: 없음 — 에이전트가 완료를 알리면 페이즈 종료

### 페이즈 1-2 — 리서치 & 아키텍처 통합
일부 변형은 리서치와 아키텍처 기획이 긴밀히 결합된 경우 페이즈 1과 2를 통합한다. 이 경우 전문 에이전트가 PM의 승인 게이트 이전에 리서치와 아키텍처 설계를 모두 수행한다. 승인 게이트는 여전히 페이즈 1-2의 끝에 적용된다.

### 페이즈 2 — 설계 검토 & 승인
**PM이 게이트를 집행한다**: 명시적 사용자 승인 없이는 실행이 없다.
- 시니어 전문 에이전트가 제안된 접근법을 제시한다
- PM이 발견을 종합해 의사결정 권고안을 만든다
- 페이즈 3로 진행하기 전 **사용자 승인 필요**
- **산출물**: 승인된 구현 계획

### 페이즈 3 — 실행 / 생성
**PM이 조정한다**: 전문가들이 승인된 계획에 따라 구현한다.
- 콘텐츠, 설계, 코드 에이전트가 자신의 도메인 작업을 수행한다
- 에이전트는 PM 개입 없이 서로 직접 핸드오프할 수 있다
- PM이 페이즈 종료 시 산출물 품질을 검토한다
- **산출물**: 주요 결과물(문서, 설계, 코드 등)

### 페이즈 4 — 전달 / 통합
**PM이 조정한다**: 전달 에이전트가 산출물을 완성한다.
- 플랫폼 통합, 게시, 배포 에이전트가 작업한다
- 프로젝트 조정자가 이해관계자 커뮤니케이션을 관리한다
- **산출물**: 전달 및 통합된 작업 결과물

### 페이즈 5 — 라이프사이클 마무리
**PM이 소유한다**: 변경된 아티팩트에 대한 거버넌스 기록을 갱신한다.
- PM이 에이전트/스킬/스크립트 변경에 대한 거버넌스 문서를 갱신한다
- PM이 결정을 `memory/YYYY-MM-DD.md`에 기록한다
- 라이프사이클 추적 대상 아티팩트의 변경분에 대해 라이프사이클 상태가 동기화된다
- **산출물**: 거버넌스 기록 갱신, 드리프트 리포트 또는 "드리프트 없음" 확인

### 페이즈 6 — 품질 보증 & 최종화
**PM이 소유한다**: 세션을 최종 완료한다.
- PM이 `audit-workspace` 스킬을 실행한다
- PM이 `validate-docs-links` 스킬을 실행한다
- 사용자에게 에스컬레이션 전 최대 2회 수정 반복
- PM이 `/sync` 파이프라인을 실행한다
- 영어 제목과 설명으로 PR을 연다
- 메모리 로그를 갱신한다
- **산출물**: 통과한 감사 리포트, 머지된 PR 또는 열린 PR 링크

## 변형 커스터마이즈 지점

각 변형은 `AGENTS.md § Phase Summary`와 각 에이전트의 `agents/<name>.md` 프론트매터에 페이즈별 전문 에이전트를 선언한다:

```yaml
# 에이전트 프론트매터 예시
phases: [1, 2]
handoff_to: [next-agent]
handoff_from: [pm]
required_skills: [skill-name]
```

PM 역할과 페이즈 0/5/6 구조는 모든 변형에서 동일하다. 변형은 페이즈 1–4에서 달라진다.

## 페이즈별 PM 진행 (Facilitation)

| 페이즈 | PM 시작 | PM 모니터링 | PM 종합 |
|-------|-----------|---------------|--------------|
| 0 | 목표 설정, 팀 지명 | 셋업 완료 확인 | 범위 문서 |
| 1 | 분석가에게 리서치 목표 브리핑 | 발견 품질 점검 | 핵심 발견 요약 |
| 2 | 승인용 발견 제시 | — | 결정 + 승인된 계획 |
| 3 | 승인된 계획 핸드오프 | 계획 이탈 시 개입 | 품질 검토 |
| 4 | 전달 목표 확인 | 완료 추적 | 전달 확인 |
| 5 | 거버넌스 기록 갱신 | 라이프사이클 드리프트 검증 | 드리프트 리포트 또는 "드리프트 없음" 확인 |
| 6 | 감사 + /sync 실행 | 문제 수정 (최대 2회 반복) | 감사 통과 리포트 + PR 링크 |
