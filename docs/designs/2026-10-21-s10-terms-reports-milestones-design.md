# 검토 2차 — 차입·여신 용어, 인센티브 단위, 부지 법규·인프라 검토, 인허가 통합, 보고서 고도화, 마일스톤 트랙 관점 (Implemented)

- **일자**: 2026-10-21
- **상태**: Implemented (decider 검토 2차 6건 — "다음의 사안들이 제대로 구현이 안된 듯 한데, 설계 및 구현을 진행해줘" + "진행해줘")
- **관련**: ADR-0061(화폐 단위 백만 KRW), ADR-0112(점수는 사람이 기록 — 값 발명 금지), ADR-0116 Phase 6(보고서 스냅샷·렌더러), ADR-0122 #1(stage SLA 계산값 전용), k-law 스킬(법령 원문 확인), `prompts/prompts.json`(s10.site_regulatory_draft), 2026-10-21-s10-s11-s12-management-upgrades-design(마일스톤 원장·공통 페이지 선행분)

## 1. 문제 — decider 검토 2차 6건

1. S10 "부채·커버넌트"는 **부채 및 여신관리** 화면 — 용어를 현업 언어로 바꾸고, 기능 충분성도 검토할 것.
2. S10 인센티브·클로백에 **왜 NPV (억원)가 나타나는가** — 저장 단위와 화면 단위가 어긋난다.
3. S10 부지·시설: **주소를 넣으면 건축법·인허가 법규를 검토**하고, **상하수도·전기·도로·물류·학교 등 인프라·인력 확보 가능성**을 평가할 수 있을 것.
4. S10 인허가/인증은 **부지/시설과 통합**해 운영할 필요가 있지 않은가.
5. S11에서 **"서버 응답이 비어 있거나 손상되었습니다"** 오류 + 보고서가 **전체 진행결과를 구체적으로** 담아야 한다.
6. S12 일정관리는 **S8~S12 전체를 다루는 사이드바** 위치여야 하고, **greenfield은 연구개발 기반 사업화, brownfield은 M&A 실사·PMI** 관점으로 운영될 것.

## 2. 결정

### 2.1 차입·여신 관리로 개명 + 충분성 보강 (질의 1)
- 탭 라벨 `부채` → **`차입·여신`**, 화면 제목 **`차입·여신 관리 (부채·커버넌트)`**, 목적문에 여신 여력 점검·투자심의 자료 전달 명시.
- 충분성 검토: 차입 목록(원금·금리·만기·커버넌트·담보/선위) + 커버넌트 여력 표(최신 시뮬레이션) + DSCR 시나리오 계산기 + 리스크 히트맵 `cov:` 연동까지 갖춰져 1차 요건은 충족. 이번에 **상환 구조(amortization) 표시**를 만기 셀에 추가(0111 컬럼이 있었으나 미표시). 상환 스케줄 표는 시나리오 계산기로 1차 커버 — 원리금 균등 스케줄 표는 범위 밖.

### 2.2 인센티브 NPV 단위 정합화 (질의 2)
- **원인**: 등록 폼이 억원을 받아 `npv_value`에 그대로 저장 → 다른 화면·자금조달이 백만 KRW(AOR-0061)로 읽어 같은 숫자가 두 뜻을 가졌다.
- **결정**: 저장 단위를 **백만 KRW로 고정**. 화면은 입력 시 ×100(억원→백만), 표시는 `fmtNpvEok`(백만→억원). 마이그레이션 **0168**이 기존 행을 ×100 보정(폼으로 입력된 억원 값). 자금조달 푸시는 환산 없이 `npv_value`를 그대로 옮긴다. `estimated_clawback`은 입력 표면이 없어 보존.

### 2.3 부지 주소·법규 사전검토 + 인프라·인력 평가 (질의 3)
- 마이그레이션 **0169**: `site.address`(법규 검토 근거), `site.infra_notes`(상하수도·전기·도로·물류 **사람 확인 메모**), `site.labor_notes`(주변 학교·인력pool 메모).
- **k-law 관점 LLM 사전검토 초안**: 프롬프트 `s10.site_regulatory_draft`(legal-counsel) 등록, `POST /sites/regulatory-draft`가 부지 정보를 근거로 검토 축(건축·환경·용도지역·인허가 절차) 초안을 **반환만**(저장 없음, 사람+k-law 원문 확인 전까지 참조 불가, 결정론 폴백 내장). 법령 조항 번호 단정 금지를 시스템 프롬프트에 명시.
- **의도적 한계**: GIS·외부 데이터 자동 평가는 도입하지 않는다 — ADR-0112(값은 사람이 확인해 기록)와 데이터 소스 미연동 때문. 인프라·인력은 **사람 확인 메모 + 점수**로 기록한다.

### 2.4 인허가/인증 ↔ 부지/시설 — 물리 통합 대신 상호 링크 (질의 4)
- 인허가/인증 추적은 **트랙 무관**(브라운필드 인증 이전 포함), 부지·시설은 greenfield 중심이라 한 화면 통합은 브라운필드에서 어긋난다. 두 화면에 **상호 링크**(부지→인허가 추적, 인허가→부지·시설 평가)를 두고, 부지 행의 주소가 법규 사전검토·인허가 마일스톤의 근거가 되도록 연결한다.

### 2.5 S11 오류 + 보고서 구체화 (질의 5)
- 오류 원인은 미적용 마이그레이션(0166 `archived_at`을 읽는 보고서 목록) + `route()` 미랩 예외. reports 3 라우트(목록/생성·compose·render)를 `route()`로 감싸 원인이 JSON으로 노출된다. **즉시 조치는 dev 서버 재시작 또는 `bun run db:migrate`.**
- `composeProjectReport`에 섹션 추가: **§8 리스크 히트맵 요약**(스냅샷 해시·상위 항목·사람 판정/완화), **§9 자금 확정성·커버넌트 여력**, **§10 인허가·인증 현황**, **§11 마일스톤 요약**(지연·임박·완료), **§12 투자심사 절차 단계 상태** — 모두 기존 원장의 계산값이며 근거 없는 숫자는 만들지 않는다.

### 2.6 마일스톤 트랙 관점 (질의 6)
- 마일스톤 화면·공통 링크·배지는 선행 슬라이스에서 이미 **S8~S12 전체 대응**(프로젝트 공통)으로 구현돼 있다. 이번에 **트랙 관점 가이드**를 추가: greenfield → "연구개발(R&D) 기반 사업화 관점(기술 검증·인허가·초기 판매·트랜치)", brownfield → "M&A 실사·PMI 관점(실사 종결·시너지 인증·핵심인재·통합)". 표시 전용이며 원장 구조는 트랙과 무관.
