# 타겟코스팅 가격 앵커 자동화 — 웹검색 근거 기반 가격 초안

- Spec ID: `2026-09-18-target-costing-price-anchor`
- Date: 2026-09-18
- Status: implemented — 2026-09-18 사용자 승인 후 동일일 구현 완료 (pr/20260918-feat-target-costing-service). 라이브 검증: 검색 제공자 미구성 환경에서 price-draft가 '검색 결과 0건 — 근거 없는 가격은 생성하지 않음' 안내와 함께 흐름 미차단을 확인(검증 기준 2).
- Origin: 2026-09-18 REQ-W2(target-costing computation service, PR #345 머지)의 후속. 시장가격 앵커가 사용자 수동 입력뿐이라는 제한을 해소한다.
- Related: ADR-0118 (LLM 결정 지원 — 제안만, 기록은 사람), ADR-0141 (eval-draft 초안 패턴 — 비영속 제안 + 사람 확정), `lib/web-research.ts` (Tavily→DDG 제공자 체인), `lib/target-costing.ts` (REQ-W2 격차 서비스), `prompts/prompts.json` (프롬프트 SSOT)

## Problem

타겟코스팅의 신뢰도는 시장가격 앵커의 신뢰도다. 현재 구현(PR #345)에서 유일한 입력 경로는 사용자 수동 입력이어서, (a) 분석가가 가격 근거를 직접 찾아야 하고 (b) 근거 없는 가격이 격차 계산에 그대로 들어가며 (c) 어디서 온 값인지 기록이 남지 않는다. ADR-0141이 실사 기술 초안에서 해결한 것과 동일한 문제다 — 근거를 모아 **제안**하고, 확정은 사람이 한다.

## 설계

### 1. 가격 증거 수집 — 기존 검색 체인 재사용

`lib/web-research.ts`의 제공자 체인(Tavily 1차 → DuckDuckGo 폴백, 비한 시 흐름 미차단)을 그대로 쓴다. 쿼리는 대상 회사/제품명 기준 3개 변형(`{회사} {제품} 단가`, `{회사} 출고가 견적`, `{제품} 시장가격 2026`) × 제공자당 최대 6건 — s7 screening_draft의 쿼리 설계 선례를 따른다.

### 2. LLM 가격 증거 추출 — `s8.price_evidence` 프롬프트 신설

`prompts/prompts.json`에 키를 추가하고 재생성한다. 모델은 검색 결과에서 **후보 단가 + 통화 + 단위(EA/세트/kg) + 출처 URL + 근거 인용문**을 추출한다. 규칙:

- 통화·단위가 특정되지 않는 가격은 후보에서 제외한다(단위 없는 숫자는 가격이 아니다).
- 출처 URL이 없는 후보는 폐기한다 — URL 없는 단가는 반환하지 않는다(REQ-W5 출처 계약과 동일 원칙).
- 후보가 0건이면 `확인 안 됨`을 반환한다(ADR-0141 철학 — 값이 없으면 값이 없다고 말한다, 절대 조작하지 않는다).

결정론 폴백: `CO_NEWBIZ_*_AGENTS` 비활성 또는 검색 실패 시 빈 제안 + 안내 문구. 흐름은 끊기지 않는다.

### 3. 비영속 초안 엔드포인트 — eval-draft 패턴

`POST /api/projects/{id}/target-costing/price-draft` — 검색·추출을 실행해 **제안 배열만** 반환한다(아무것도 영속화하지 않음, ADR-0141 계약). 각 제안: `{unit_price, currency, unit, source_url, source_name, quote, confidence}`. 사람이 제안을 검토해 클릭하면 폼에 채워지고, 기존 `POST /api/projects/{id}/target-costing`(source=`peer_benchmark`, rationale에 출처 URL 인용)으로 확정한다 — 확정 경로는 REQ-W2에서 이미 구현된 것을 그대로 쓴다.

### 4. 증거 보존 — 마이그레이션 0116

확정 시 채택한 제안(들)을 `target_costing_analysis.price_evidence_json`(nullable, 신설)에 보존한다: 출처 URL·인용문·검색 시각. fs 게이트가 "이 가격이 어디서 왔는가"를 리뷰할 수 있는 근거 행이 된다. 기존 행은 NULL = 수동 입력, 변경 없음.

### 5. UI — TargetCostingPanel 확장

폼 상단에 `가격 초안 (웹검색)` 버튼 추가. 결과는 후보 카드 목록(단가·통화/단위·출처 링크·신뢰도)으로 렌더링하고, 카드의 `이 가격 사용`이 폼의 시장가격·출처·근거를 채운다. `확인 안 됨`이면 근거 부족 안내를 표시하고 폼은 수동 입력을 유지한다.

### 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| DART 공시 자동 단가 추출 | 단품 단가는 공시에 공개되지 않음 — 추정의 근거가 없음 |
| 유료 시장 DB(NTA/EMIS 등) | 라이선스·비용 — 운영 환경에서 보편적으로 불가 |
| 프록시 체인 단독 추정 | 가격 노드 교정 데이터가 아직 없음(별도 설계 선결제 필요) |

### 경계 (비협상)

- 초안·제안은 결정 지원이며 채택·기록은 사람이다(ADR-0053/0118).
- 확정 전 영속화 없음: 초안 단계에서 DB에 쓰는 것은 없다.
- 출처 URL 없는 가격 제안은 생성 단계에서 폐기된다.
- 검색 불가 환경에서 흐름은 미차단된다(수동 입력 유지).

## 구현 단계

| 단계 | 범위 |
|---|---|
| 1 | 프롬프트 키 + price-draft 엔드포인트(검색·추출·제안) |
| 2 | 마이그레이션 0116(`price_evidence_json`) + 확정 시 증거 보존 |
| 3 | TargetCostingPanel 초안 버튼·후보 카드·폼 채움 |

## 검증 기준

1. 출처 URL 없는 후보는 제안에 존재하지 않는다.
2. 검색/LLM 불가 환경에서 price-draft는 빈 제안 + 안내를 반환하고 오류로 끝나지 않는다.
3. 확정 전 DB 쓰기가 없음을 테스트로 증명한다.
4. 확정 행의 `price_evidence_json`이 채택 근거(URL·인용)를 보존함을 테스트로 증명한다.
