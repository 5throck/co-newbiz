# S8 기술적 타당성 T2~T5 — S9 판정 기록·S8 탭 반영 설계 (Implemented)

- **일자**: 2026-10-20
- **상태**: Implemented (2026-10-20 — round 5c 최종: S8 T1~T6 탭화, T2~T5는 S9 체크리스트 롤업으로만 파생, T1은 S9 역량 판정 커버리지. round 4의 별도 기록 블록·`technical-items` 라우트·판정 사이드카 lib는 **철회**되었고 마이그레이션 0157의 칼럼은 미사용으로 남는다)
- **원 질의**: decider round 4 — "해당 내용은 S9로 이동해서 통합되어야 하는 내용이 아닐까", "T1~T6가 S8에 탭 형태로 볼 수 있어야"
- **관련**: ADR-0169 (S8 기술·재무 렌즈), 2026-10-14-s8-technical-financial-lens, 2026-10-19-brownfield-capability-dd-design (같은 사이드카 패턴)

## 1. 문제

S8 기술적 타당성 렌즈(ADR-0169 release 1)는 T2 기술 성숙도(TRL)·T3 핵심 인력·설비·시설·T4 지식재산·라이선스·T5 인허가·인증을 "다음 릴리스에서 입력 기능이 열립니다"로 비워 두었다. 이 항목들의 근거(실측·설비 잔존·IP 검색·인허가 현황)는 모두 S9 실사·검증의 영역이므로, S8에서 따로 판정 입력을 열면 같은 사실을 두 단계에서 이중 기록하게 된다 — 필요 역량 판정을 S9 capability-dd로 옮긴 것과 같은 문제다.

## 2. 결정 (round 5c 최종 — decider: "S9의 실사 구조에 맞게 S8 항목이 반영되어야 한다")

- **S9 구조는 바꾸지 않는다.** T2~T5의 판정은 S9에 이미 있는 체크리스트 항목 판정이다 — 별도의 "항목 판정" 기록 표면·라우트·사이드카를 두지 않는다 (round 4에서 추가했던 S9 기술 탭 블록과 `GET/PUT /technical-items`는 철회).
- **구성 항목 매핑이 S8↔S9 연결선이다.** `technical-item-constituents.ts`: T2 기술 성숙도 = tdd-03·04 / T3 핵심 인력·설비·시설 = tdd-05·07(기술 실사) + hdd-01·03(인사 실사) / T4 지식재산·라이선스 = ldd-10·11·12(법무 실사) / T5 인허가·인증 = tdd-08·06(기술) + ldd-15(법무) / 공통 증적 tdd-01·02(T6). 각 항목은 **자기 실사 탭에서** 사람이 판정한다.
- **S8은 롤업으로만 파생.** `rollupConstituentStatuses`: 하나라도 미충족 → 미충족, 미판정 있음 → 판정 대기, 전부 충족/해당없음 → 충족. 이 프로젝트의 체크리스트에 실제 존재하는 구성 항목만 센다(`listDdWorkspace`). 완료된 롤업은 judged, 부분은 미판정(`구성 항목 j/N 판정`), 구성 항목 없음은 기존 폴백.
- **S8 탭 뷰는 S9 구조를 그대로 비춘다.** T2~T5 탭은 구성 항목을 **실사 탭별로 묶어**(기술 실사 n/m · 인사 실사 n/m · 법무 실사 n/m) 각 항목 문구와 판정 상태를 보여주고 S9로 링크한다 — S8에는 기록·판정 affordance가 없다.
- **T1(브라운필드)** 은 S9 capability-dd 판정 커버리지에서 파생(전부 해소 → 충족, 부분/미해소 → 주의, 미완료 → 미판정). S8 역량 패널은 S5/S7 기반 요약과 "처리할 것/전체" 필터를 숨기고 S9 커버리지 줄만 보인다.
- **T6 = `S9 실사 반영 현황`** (round 6: "짝 검증" 표현 철회, 두 트랙 공통 라벨). T2~T5 롤업이 모두 완료되면 충족, 그 전까지 `S9 실사 반영 N/4`. S8 더보기의 유일 항목 `요약`은 제거(개요 귀속은 `extraSegs`로 유지).
