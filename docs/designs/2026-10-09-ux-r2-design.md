## 1. Page contract (applies to every route)

| Element | Rule |
|---|---|
| Document title | One per page, set through a server `layout.tsx` (`metadata` / `generateMetadata`); the root template adds ` · 신규사업 검토`. |
| h1 | Exactly one, visible. |
| Breadcrumb | Shared `components/Breadcrumb.tsx`; deal pages use `DealBreadcrumb` (`보드 › 안건 › 단계 › 탭`). The last item is `aria-current="page"`; earlier items are real links. |
| Primary action | One filled action per page (`PrimaryAction`); disabled primaries show their reason as text. |
| Empty state | Explains the next step and offers the create action, never a dead end. |
| Back | One consistent parent-based back (topbar) plus the breadcrumb. |

## 3. R2-A decisions

### 3.1 New market analysis (items 1 and 2)

- `/market?new=1` renders the S1 screen with the new-industry form open, scrolled into view and focused. It is never auto-redirected into an unrelated deal. The industry master is global, so the analysis needs no deal.
- The board primary `＋ 새 검토 시작 (시장분석부터)` links to `/market?new=1`. Path: board click 1, type the name, `분석 범위 선택` click 2, `이 산업만 분석` click 3.
- Picker pages `/market`, `/opportunities`, `/synergy`, `/route-decision` (and `/greenfield`, `/brownfield`) share one layout: breadcrumb, h1, a create action as the primary, an explanatory line, then the deal list. Create actions: market `새 시장분석 시작`; opportunities `새 기회 등록` (`/opportunities?new=1`); synergy `그룹·계열사 프로파일 등록`; route-decision, greenfield, brownfield `새 검토 시작 (시장분석부터)` (S3 to S7 need a deal that already passed S1 and S2).
- The sidebar marks `검토/안건 보드` active on the deal-less flat routes (`DEAL_FLOW_FLAT_ROUTES` in `lib/navigation.ts`) and the topbar gives them a contextual back to the board.

### 3.2 Stage rail S8 to S12 (item 3)

`/deals/{id}` carries the opportunity id; S8 to S12 need the project id. `useDealContext` reads `project_id` from the opportunity (requests are de-duplicated for 3 s). A promoted deal links to `/projects/{project_id}/...`. An unpromoted deal shows those stages as non-links (`aria-disabled`, a visible `승격 후` label and a title with the reason); an unresolvable deal says so. The handoff strip uses the same resolver.

### 3.3 S3 (item 4)

The empty state and the new-analysis form no longer refer to a non-existent `회사 등록` button. They state the order `그룹 → 계열사 → 시너지 분석` and link to the group/affiliate profile surface (`/deals/{id}/s3?surface=company`, or `/our-company` outside a deal). `분석 시작` stays disabled until a target is chosen and now shows the reason next to it with the same link.

### 3.4 S2 row action (item 5)

Each row advances its own opportunity: an identified row offers `매력도 평가` (opens the detail with the score field focused), an assessed or selected row offers `S3로 진행` (`/deals/{rowId}/s3`). The header primary names its target (`S3로: <기회명>`).

### 3.5 Back targets and breadcrumbs (item 6)

The opportunity detail's back goes to `/deals/{id}/s2` (`← S2 목록으로`); the topbar back for it reads `S2 기회 발굴`. The detail gets an h1, the breadcrumb and the stage rail. The S1 report gets the breadcrumb (`… › S1 시장분석 › <산업>`), the stage rail, `← 산업 목록으로` and the primary `다음: S2 기회 발굴 →`. The report heading is now the page h1.

### 3.6 Known target and orphan routes (items 7 and 8)

Known-target entry (`/opportunities?known_target=1`): the registration form is rendered at the top under an explanatory banner; its first field is focused. Guide steps on the opportunity detail are underlined links. Opening the form from `＋ 기회 등록` now also scrolls and focuses (walkthrough F9).

## 5. Accessibility

- Breadcrumb is a `nav` landmark labelled `현재 위치` with an ordered list; the current page uses `aria-current="page"`; separators are `aria-hidden`.
- Disabled rail stages are `aria-disabled` spans with a visible text label (not colour alone) and a title; they are not focus stops. Row actions carry the opportunity name in screen-reader text (`매력도 평가 — <기회명>`).
- Focus management: entry forms receive focus after `scrollIntoView`; the moved-route notice is a `role="status"` region with a keyboard-reachable `닫기` button.
- Every touched page has exactly one h1 and a distinct document title (WCAG 2.4.2, 2.4.6, 2.4.8).
- Notice and banner colours use `--surface`, `--fg`, `--border`, `--accent` (no `--primary-bg`, which fails dark contrast until R2-C). New surfaces were scanned with axe (light): 0 serious/critical.
- Targets keep the 44 px mobile minimum through the existing `.btn-ghost`/`.back-link` rules.
