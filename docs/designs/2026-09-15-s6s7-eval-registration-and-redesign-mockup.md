# S6/S7 — 후보 등록 시점 평가 준비 + 재무 기준 구체화 + UX 재설계 목업

## 배경

기존 S7 재무·기술 평가 레이어(ADR-0139)는 `md_company`/평가 기준 카탈로그를
Short List 승격 시점에만 준비했다. 사용자는 Long List 등록(목표 시장 정의
탭에서 후보를 검색·확정하는 시점) 즉시 재무 데이터 측정이 가능해야 한다고
요청했다. 재무 평가 빌트인 5항목("매출성장률/영업이익률/순이익률/부채비율/
영업부문")도 실제 DART 데이터(5개년 매출·영업이익·부채 추이)와 연결되지
않은 추상 라벨이었다.

## 변경 사항

1. **등록 시점 준비**: `resolveOrCreateCompany()`를 Short List 승격 라우트
   에서 추출해 `createTarget()`(타겟 생성·회사 마스터 확보·평가 기준 시딩을
   한 트랜잭션으로 묶음)에 내장 — Long List 등록 즉시 재무 참고 패널이
   작동한다. 4인 설계 검토(회의) 2라운드에서, 웹검색 확정 라우트가 실제로는
   `createTarget()`을 호출하지 않고 자체 INSERT를 쓰고 있었다는 사실이
   드러나 두 등록 경로를 통합했다.
2. **재무 기준 구체화**: 빌트인 재무 5항목을 3항목(매출액/영업이익/부채
   규모·5개년 추이)으로 교체하고, 비율 지표(영업이익률·순이익률·부채비율)는
   참고 패널에 남긴다(마진 붕괴 신호를 놓치지 않기 위함). 이미 시딩된
   오퍼튜니티를 위한 1회성 백필 스크립트 추가.
3. **화면 재배치**: 후보 검색·확정을 Long List 탭에서 목표 시장 정의 탭으로
   이동. Long List 행에 재무/기술 평가 진행률 배지와 DART 참고 패널 추가.
   Short List에 t-01/t-02/t-08 발췌 "인수 가능성" 참고 섹션 추가.
4. **UX 재설계 검토 목업**: ux-designer-agent가 현재 구현(주요 액션 위계
   부재, 확장된 Long List 행의 과밀)을 비평하고 드로어 기반 평가 워크스페이스
   안을 제시 — `/brownfield-mockup`(비메뉴 라우트, 정적 데이터, API 미호출)
   으로 실제 컴포넌트·토큰을 사용해 구현, 검토 후 승인/폐기 결정 대기.

## 영향

- 스키마 변경 없음(`brownfield_target.company_id`는 조회 시 JOIN으로 계산,
  컬럼 추가 안 함) — ADR 불필요.
- Short List 승격 게이트(`screeningSummary`)는 변경하지 않음 — 평가 요약은
  참고 정보일 뿐 하드 게이트가 아니다(경계 #2).
- 기존 `brownfield-eval-criteria.test.ts`/`wave0-data-contract.test.ts`에
  회귀 테스트 추가, 전체 유닛 테스트 통과.

## 상태

Implemented — 재무 기준 구체화·등록 경로 통합·UI 배치는 이번 커밋에 반영.
`/brownfield-mockup` 재설계안은 검토용이며 실제 반영 여부는 후속 결정.
