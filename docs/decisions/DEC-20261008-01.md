## Promotion rule (design §8)

`CO_NEWBIZ_COMMITTEE_AGENTS` may become default-on only when **all** of the following hold on the **same** golden version, model id and prompt hashes, over `bun run eval --llm --suite committee --repeat 3`:

| Criterion | Threshold |
|---|---|
| Schema-valid rate (after repair) | ≥ 99% |
| Member vote agreement with expected | ≥ 80%, and not below deterministic-mode agreement |
| Kill-criteria hits surfaced in deliberation | 100% recall |
| Run-to-run vote flip rate | ≤ 10% |
| Explicit "could not verify" declarations present | 100% of sessions |
| Median cost per session | within the `config/llm-pricing.yaml` budget line set by PM |

## Status: not promoted

- **No priced model.** The configured model has no entry in `config/llm-pricing.yaml`, so cost is recorded as `null` and the median-cost criterion cannot be evaluated. Cost is never guessed (design §6).
- **No LLM baseline.** No `--llm` committee scoreboard exists under `docs/reports/eval/`. Every LLM criterion above is unmeasured.
- Known label caveat: the pilot-008 Screening kill expectation is a `known_disagreement` (golden v1.1.0, `docs/audits/2026-10-08-pilot-008-hhi-presumption-vs-certain-block.md`). The kill-recall criterion must be computed on the scored set and must name this exclusion.

## Conditions

- A promotion must supersede this record with a new DEC that cites the scoreboard file (golden version, model id, prompt hashes, repeat count).
- A change of model id or of any prompt hash voids a promotion until the suite is re-run.
- Human gate approval and the investment decision are unchanged either way (design boundary 2).
