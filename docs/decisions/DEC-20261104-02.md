## Context

- The market-sizing pipeline LLM block in both local env files set the provider to
  `custom` while pointing the base URL at an Anthropic-compatible endpoint. With
  `custom`, the client calls `{base}/chat/completions`; against
  `https://api.z.ai/api/anthropic` that path does not exist and the call returns 404.
- Both files also carried a trailing enum comment on the same line as the provider key.
  The project has two env loaders — `scripts/lib/env-keys.ts` and
  `app/web-next/lib/root-env.ts` — and both trim surrounding whitespace but do not
  strip inline comments. The comment therefore became part of the value: the value
  reaching `process.env` was 64 characters of provider name plus comment text, not a
  valid provider token.
- `app/web-next/.env` used the singular key `CO_NEWBIZ_COMMITTEE_AGENT`. No code reads
  that name; the application reads only the plural `CO_NEWBIZ_COMMITTEE_AGENTS`, so the
  configured committee LLM mode was unreachable.
- The files in scope are gitignored local configuration. There is no repository
  artifact change and no feature surface, so the change carries no design doc.
- **Rule applied: ADR-0074 (Universal Design Gate).** The gate asks whether a change
  carries spec activity; this one is answered at Row 0 by determining that the change
  surface is not a repository artifact. `rules_applied` is left empty because this
  variant's `validate-decisions.ts` accepts only `<PREFIX>-R<N>` rule IDs from the
  variant rule registry, and ADR-0074 is an ADR reference, not a rule ID.

## Determination

- **Design Gate Row 0: no design doc applies.** The changed files are gitignored local
  configuration; no repository artifact changes, and no `docs/designs/` record applies.
- The ruling is a **configuration correction, not a feature**:
  - the Anthropic-compatible base URL requires provider `anthropic`;
  - the inline comment leaked into the value because the two project env loaders trim
    but do not strip inline comments;
  - the singular `CO_NEWBIZ_COMMITTEE_AGENT` key was unreachable.
- Applied edits, confined to the two env files:
  - `.env`: the enum comment moves to its own line above
    `CO_NEWBIZ_LLM_PROVIDER`, and the key value becomes `anthropic`.
  - `app/web-next/.env`: the same comment move and provider correction, plus the key
    rename from `CO_NEWBIZ_COMMITTEE_AGENT` to `CO_NEWBIZ_COMMITTEE_AGENTS` with its
    value unchanged.
- Verification is behavioural, not textual: the value is confirmed through the project
  loader (`app/web-next/lib/root-env.ts`), which must resolve the provider to
  `anthropic` at exactly 9 characters — proving the polluted 64-character value is gone.

## Alternatives considered and rejected

- **Switch the base URL to z.ai's OpenAI-compatible surface, keep provider `custom`**:
  rejected. The operator holds an Anthropic-plan credential, and the anthropic path was
  verified to exist; changing the endpoint would trade a verified route for an
  unverified one.
- **Leave the inline comment in place**: rejected. Verified that `root-env.ts` lifts the
  64-character polluted value into `process.env`, so the defect would survive a
  provider-value-only fix.
- **Leave the singular key**: rejected. The committee LLM mode silently stays off
  because nothing reads the singular name.

## Out of scope — recorded for follow-up, not fixed here

- Neither env loader strips inline comments (`scripts/lib/env-keys.ts`,
  `app/web-next/lib/root-env.ts`). This correction avoids the defect for these two
  files; the loaders can still corrupt any future inline-commented value.
- `CO_NEWBIZ_API_TOKEN` now holds a well-formed personal token with the `cnb_pat_`
  prefix (72 characters — length recorded, the value never is) rather than the
  sample placeholder it held when this record was written.
- `.env.prod` now exists (13 keys, mode 600), so the production variables the root
  `.env` documents do have a file to live in.
