## Context

- The 2026-11-04 full project review ran the project's own validator battery plus four
  parallel review domains (architecture/scaffolding, standards/lifecycle, automation,
  docs/security). The machine baseline was green; the findings that mattered were gates
  that reported success while exercising nothing.
- Four of the thirteen findings had a clear, low-risk fix available in-session: a
  regression in the `scripts` test-suite scan roots (a defect the 2026-09-20 review had
  already fixed once), a typecheck gate that had skipped on every run since its
  introduction because its baseline file was never committed, a CI job that had drifted
  from every other job's pinning and timeout conventions, and a context document citing a
  superseded flow.spec version and stale skill counts.
- Nine findings had no in-session fix path: three are suspected template defects
  (upstream channel), and the rest need design-level decisions or multi-cycle work
  (skill lifecycle backfill of 75 records, a findings ledger, an evidence channel, an
  84-error type regression triage).

## Determination

- **Fix now**: the four restoration/hygiene items, under one design doc, verified by the
  full validator battery before the gate proposal.
- **Upstream**: the three template-suspected defects, as U-20261104-001..003, with no
  local patch applied (the local tree keeps the upstream behaviour until the template is
  fixed and delivered by `upgrade-project`).
- **Deferred**: the systemic items, recorded in the review report and the session memory
  log rather than as tickets, because `bun scripts/ticket.ts` is workspace-root (L0) only
  in a variant project.
- **Ratchet**: each of the four fixed items now has a standing check rather than a
  one-time repair — the empty-suite guard, the real typecheck baseline, and the
  registry text aligned to the code. A `script-gap` finding that reappears as an agent
  finding in the next review means that check did not land.
