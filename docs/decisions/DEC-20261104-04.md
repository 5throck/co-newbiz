## Context

- The PR #803 risk-officer review flagged that `scripts/lib/env-keys.ts`
  matches key lines with `/^([A-Z_]+)=(.*)$/` — no digits — so a digit-bearing
  key line can never even be captured by that loader, while
  `app/web-next/lib/root-env.ts` and `app/web-next/prisma.config.ts` already
  match `[A-Z_0-9]+`. DEC-20261104-03 recorded the defect as deferred Row 1,
  explicitly out of scope for the shared-parser change.
- Design 2026-08-31-pipeline-execution-environment §2.5 accordingly recorded
  the limitation as "the deferred Row 1 defect ... not a supported shape".
- The user asked to close it. The PM ruled on scope; this record, authored by
  the platform-lead as the technical AI-2nd seat, is Row 0 of that closure —
  design-gate activity only. No implementation file is modified by this
  ruling, and the working tree carries the amendment to the registered design
  plus this record.

## Determination

- **Closed under the existing spec, not a new design doc**: the key-charset
  closure completes §2.5's reader coverage on the same three seams Row 0
  already reviewed; a completion of a registered design belongs in that
  design, re-registered via `spec-register.ts`.
- **Both layers widen, not one**:
  - Line match: `scripts/lib/env-keys.ts:33` (pre-change) `/^([A-Z_]+)=(.*)$/`
    → `/^([A-Z_0-9]+)=(.*)$/`, matching the other two readers.
  - Family sub-patterns widen to `[A-Z_0-9]+` in the same change:
    `PIPELINE_ENV_KEYS` `CO_NEWBIZ_LLM_[A-Z_]+` → `CO_NEWBIZ_LLM_[A-Z_0-9]+`
    (env-keys.ts, pre-change `:17-18`); `LLM_KEY` likewise (root-env.ts,
    pre-change `:19`); `NOTIFY_KEY` `/^NOTIFY_[A-Z_]+$/` →
    `/^NOTIFY_[A-Z_0-9]+$/` (root-env.ts, pre-change `:24`). NOTIFY is widened
    because the prefix rule's stated purpose is that channel names grow — a
    digit-suffixed channel name must not be a silent trap.
- **Exact names stay exact**: the named adapter credentials in
  `PIPELINE_ENV_KEYS` (DART_API_KEY, ECOS_API_KEY, KRX_API_KEY, KOSIS_API_KEY,
  DATA_GO_KR_API_KEY, LAW_API_OC, TAVILY_API_KEY) are not widened;
  `app/web-next/prisma.config.ts` is untouched (already `[A-Z_0-9]+`).
- **Security framing**: the widening stays inside families that are already
  prefix-wildcarded (`CO_NEWBIZ_LLM_*`, `NOTIFY_*`); no new family is
  admitted; no live key on disk has digits (0 digit-bearing key lines in
  `.env`, `.env.prod`, `app/web-next/.env`, grep-verified 2026-11-04).
- **Row 1 (implementation) is a separate PM dispatch after user approval.**

## Consequences

- Digit-bearing family keys become reachable through all three loaders; a
  non-family digit key (`FOO_2_API_KEY`) stays rejected in each.
- §4 gains a digit-key verification bullet, so the change carries the same
  fails-before/passes-after evidence bar Row 0 met.
- The prefix-wildcard surface grows by digits only: every key the widened
  patterns admit sits inside a family that was already wildcarded, so the
  review delta is one character class, not a new admission surface.
