## Context

- PM dispatched this Row 0 under the Design Gate (ADR-0074) after a user complaint at S6
  brownfield: the AI-generated `목표 시장 정의` draft framed the target market technically —
  certifications and oligopoly implying "large companies with track records" — instead of by
  business viability. The root causes were verified in code and against the dev DB before this
  ruling (design §2, with file:line); this DEC fixes the rulings so Rows 1+ implement without
  re-litigation.
- The verified pin discrepancy is the sharpest evidence: the draft route resolves S1 by
  `market_scope` name text, and on the pilot opportunity that text matches a DIFFERENT industry
  row (same name, different id) whose latest completed version anchors $38.66B — while the
  opportunity's person-confirmed `sizing_version_id` pins industry v7 at $39.88B. The draft has
  been quoting a stale figure from the wrong industry record.

## Determination

1. **R1 — viability axis added to the S6 definition (ruling adopted as designed).** The prompt
   schema gains `viability`; the saved record gains `financial_criteria`; flow.spec is
   untouched and the coherence reading (S6 output `선정 기준` includes the financial criterion;
   S7 t-08 consumes it) is argued in design §8.
2. **R2 — technical framing demoted to S7 screening.** t-05/t-07 and the ADR-0139 eval layer
   remain the home of capability conditions; the prompt and the procedure bump both state the
   boundary explicitly.
3. **R3 — pinned-version resolution order fixed.** pinned → industry-FK → name fallback →
   honest unset, mirroring gate-brief's ADR-0180-slice-6 resolver; provenance (resolution,
   version identity, grade, anchor) returned on every draft; call-site version constant
   `s6.universe_criteria_draft@2` follows the MINUTES_PROMPT pattern.
4. **R4 — honest absence, never substitution.** 0-row fact_industry is stated as a gap line
   naming the producing S1 activity; `검증 필요` + named data is the required form of the
   viability condition when evidence is missing.
5. **R5 — procedure bump sequenced with implementation.** The exact yaml diff (1.0.0 → 1.1.0)
   is specified in design §6.2 and applied by the implementation dispatch per the verified
   house convention (procedure edits land with implementation — 255558ff precedent);
   governance-registry regenerated at that time. The wiki refresh is a recorded follow-up.
