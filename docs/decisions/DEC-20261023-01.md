## Basis and limits

- The ruling rests on PM-verified code facts of 2026-10-23: 20 `completeOrFallback` route files (19 stage-artifact + `api/agents/query`), 10 lib pipeline modules, the 11-agent hardcoded allowlist (`pm-router.ts:64-66`), `classifiedBy: "llm" | "rules"` (pm-router.ts:18), the optional `agent` parameter across the five llm.ts entry points, 39 prompt entries with exactly 2 `agent: null` keys (`s8.business_case_prose`, `committee.position`), the unwired `generate-agent-registry.ts --check`, and `agent_run` lacking an `agent_key` index.
- The decider shaped the final configuration across successive refinement rounds on 2026-10-23: gateway mode (A status quo / B per-call LLM classification / C deterministic catalog + mandatory declaration), console scope (read-only vs dry-run lane), and UX grounding (benchmark-first). This record closes the gate-moment trail; ADR-0183 carries the decision itself.
- Acceptance covers the design row (Row 0) only — no runtime code has landed. Implementation rows (llm.ts signature tightening, catalog generator, parity gates, console, dry-run store, migrations 1-3) must cite the design-of-record §6 and re-verify these facts if the tree has moved.
- The three DB migrations are governed by the schema-change ADR trigger; ADR-0183 is that ADR. Any additional table or column beyond the three enumerated requires a new ADR.
