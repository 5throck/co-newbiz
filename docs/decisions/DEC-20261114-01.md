## Context

Verified defect (live diagnostic run 2026-11-14, quoted in the PM dispatch): with
Tavily quota-exceeded (HTTP 432) and Brave at 429, Serper unkeyed and DuckDuckGo
healthy, `researchSourcesDetailed(["drone market CAGR forecast consensus", …], 5)`
returned `{ n: 5, quotaExceeded: true, providers: [tavily=quota_exceeded(432),
brave=429, serper=no_key, ddg=ok] }` with five relevant market-report sources
(imarcgroup / marketresearchfuture / technavio drone-market pages) — yet the S1
tiers received zero excerpts, because `quantitativeExcerpts`
(market-sizing-pipeline.ts:544-554) discards everything on `quotaExceeded`:

```ts
if (r.quotaExceeded) return []; // ← the defect: the chain's DDG sources are thrown away
```

The consequence is user-visible: the step 5 CAGR-consensus tier (~:1162) and
step 5-B forecast tier (~:1231) skip their extraction calls, fall through to the
honest LLM-prior tier, which returns null on markets it cannot vouch for — so no
`captured_from='web_research'` reference is ever saved (R9) and the top-down
consensus stays "not entered" (the Korean copy, translated: top-down consensus
not entered) across every re-analysis.

Verified code facts (worktree, 2026-11-14):

- The provider chain already degrades correctly and truthfully:
  web-research.ts:410-441 walks Tavily → Brave → Serper → DDG (→ Playwright when
  opted in per call, :425-428), merges sources across providers, and carries
  `quotaExceeded` as a side-channel cost flag aggregated over the whole walk
  (:415, :422, :433) — never cleared by later providers' success.
- The chain-integrated headless fallback precedent and its option seam exist:
  `ResearchOptions { playwright?, deadlineAt?, playwrightQueries? }`
  (web-research.ts:400-407), `PLAYWRIGHT_MIN_REMAINING_MS = 8_000` (:408),
  `WEB_SEARCH_PLAYWRIGHT_ENABLED` opt-out (:188-193), single-browser queue
  (:195-206); company-profile-pipeline.ts consumes them at :519-533 with
  `PROFILE_SEARCH_DEADLINE_MS = 30_000` / `PROFILE_PLAYWRIGHT_QUERIES = 2`
  (:286-287).
- The S1 helper has four call sites — step 2 anchor (:935), step 4 growth
  context (:1052), step 5 consensus (:1162), step 5-B forecast (:1231); 10
  tracked queries per run is the pinned R7 bound
  (tests/unit/market-sizing-web-grounding.test.ts).
- Excerpts are the ONLY path into the matrix for searched values (R2
  `validateExcerptItems` per-item validation; "never invent values absent from
  the excerpts" — Korean copy, translated), so keeping more sources cannot
  admit unvalidated numbers.

## Basis

- ADR-0074 (Design Gate): Row 0, non-exempt — the change alters the meaning of
  an R7 clause in the S1 quantitative-grounding protocol (2026-11-06 design
  amendment territory) and extends another pipeline's design scope, so a design
  doc of record precedes the code.
- Non-negotiable #4 (data confidence caps the RAG grade): unchanged — every
  excerpt-sourced value still passes item-level extraction validation with URL
  and index pinning; the fix changes WHICH sources are offered to that
  validation, never what enters the matrix without it.
- Boundary #2 (a person decides): unchanged — the consensus still enters as
  "before original-text verification" (Korean copy, translated)
  and the LLM prior still refuses to fabricate; no gate, verdict or grade
  semantics move.
- ADR-0098: this record and its design doc lead with the conclusion and keep
  KNOWN/INFERRED/ASSUMED/UNKNOWN separate; the design doc is the extended form.

## Determination (design decisions ruled)

- **D-A** Consumption rule (market-sizing-pipeline.ts): the helper returns
  `r.sources` when non-empty regardless of `quotaExceeded`, `[]` otherwise;
  try/catch and the `quantSearchQueryCount` accounting untouched; the contract
  is pinned through an exported pure helper (`excerptsFromChainResult`) so the
  quota-present-but-sources-present case is a first-class unit pin.
- **D-B** Headless rescue scope: `quantitativeExcerpts(queries, { deadlineAt? })`
  forwards `{ playwright: true, deadlineAt, playwrightQueries: 2 }` only when a
  deadline is provided; `runSteps` computes `webGroundingDeadline = Date.now() +
  30_000` once before the top-down consensus block and passes it to the step 5
  and step 5-B call sites. Steps 2/4 keep the no-playwright behavior. Constants
  mirror the profile pipeline's values (`SIZING_SEARCH_DEADLINE_MS = 30_000`,
  `SIZING_PLAYWRIGHT_QUERIES = 2`).
- **D-C** Unchanged: `researchSourcesDetailed` and the provider chain (option
  consumers only), R1 recorded-reference precedence, R2 per-item validation,
  R9 single web_research persist, LLM-prior tiers and wording, section
  confidence grades/notes, the 10-query R7 bound, and all four call sites'
  query lists.
