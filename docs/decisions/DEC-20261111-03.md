## Context

- PM dispatched this Row 0 under the Design Gate (ADR-0074) to fix the four Track-A owner decisions of the
  improvement plan: the intake entry surface, admin MFA, admin API-token issuance, and the bootstrap admin
  password handling. The owner was put to the question; no answer arrived by dispatch time, so per the
  dispatch every ruling below is a **PM best-judgment default**, recorded here as the decision basis with a
  **revisit-on-owner-input** obligation — an owner answer supersedes the affected ruling without a new gate.
- Every substantive claim behind the rulings was verified against the code before design (design §2,
  with file:line): the two board CTAs and their landing flows; the opportunity-creation seams and the
  append-only audit writer; migration numbering (latest 0189 → intake takes 0190); the two token-issuance
  seams including the unvalidated raw-scopes hole on the admin-on-behalf route; the validation-time role
  re-check that must stay unchanged; the bootstrap plaintext banner and the two runbook log-scrape
  instructions; and the house modal accessibility pattern.

## Determination

1. **E1 — intake record, not a stage (ruling adopted as designed).** A `deal_intake` row is created by a
   board modal on both CTAs before/with S1, links to the opportunity at `POST /api/opportunities`, renders
   as the origin line on `/opportunities/[id]`, and is audited (`intake_created` / `intake_linked` /
   `intake_link_refused`). No S0, no gate change. Schema in ADR-0197; flow, API, UI, i18n, accessibility,
   and tests in the design §3.
2. **E2 — admin token issuance forbidden (ruling adopted as designed).** Both issuance seams close for
   admins (self-service all-scopes refusal; admin-on-behalf POST 403 + audit); list and revoke remain;
   `validateApiToken` unchanged so existing tokens stay valid until expiry — design §4 names the exact
   lines and the tests that must flip (`token-issue-access.test.ts:10`, `api-tokens.test.ts:196-206`).
3. **E3 — bootstrap password to a 0600 file (ruling adopted as designed).** The plaintext log line is
   removed (not masked); the password is written once to a 0600 file next to the resolved DB (env
   override honored); file-write failure aborts first-boot admin creation; `must_change_password` stays
   forced; `deployment.md` :65 and :96 give the operator the file path — design §5.
4. **E4 — MFA deferred (accepted-risk record).** No code. Compensating controls today: PBKDF2 hashing,
   forced `must_change_password`, session auth, and (this batch) the E2 issuance lockout. Revisit on any
   admin-account incident or the next security-review round; factor choice (TOTP vs passkey) and recovery
   custody are the first design questions when it reopens.
5. **Binding basis note.** All four rulings stand only until the owner answers; Rows 1+ implement them as
   written, and a later owner reversal is executed as a small follow-up batch (design §9 lists the reversal
   cost per item).
