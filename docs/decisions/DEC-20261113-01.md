## Context

- Today's S1 drone re-analysis on dev failed: all 44 pipeline LLM calls got HTTP 400 because the
  configured provider (`openai-compatible` / `https://api.openai.com/v1` / `gpt-6.1-terra`) rejects
  `max_tokens` (`app/web-next/lib/llm.ts:509,548`), while protected-rerun (ADR-0131) kept the old
  version. During the diagnosis the user found the SAME config block maintained in BOTH `.env`
  files and asked for unification.
- PM verified the duplication and the loader mechanics before dispatch; this ruling re-verified
  every specific claim against the working tree on 2026-11-13 (file:line anchors in the design doc,
  §2).
- Three facts found during re-verification sharpen the ruling beyond the dispatch brief:
  1. `CO_NEWBIZ_COMMITTEE_AGENTS` has no consumer — ADR-0196 amendment decision 10 removed the mode
     env var entirely (CHANGELOG 2026-11-09, PR #845); the active root `.env:120` line is a local
     leftover the sample cleanup could not reach (env files are gitignored).
  2. The trailing spaces are behavior-neutral: every current reader trims (`parseEnvValue`
     env-value.ts:45-46; dotenv 16.3.1 `parse` trims; `readKeyFromEnvFile` trims; env-check trims),
     so they are fixed by file normalization, not parser code.
  3. Next.js 16.2.2 loads `app/web-next/.env` BEFORE evaluating `next.config.ts`
     (`node_modules/next/dist/server/config.js:1182` precedes the config-module import), so
     `CO_NEWBIZ_DIST_DIR` and any app-file value are visible at config-eval time while the root
     `.env` is not (the root loader runs in `instrumentation.ts` afterwards).

## Determination

1. **Row 0: non-exempt, design of record registered.** The unification is architectural (loader
   allowlist semantics, a new pre-flight check, boot behavior) and therefore requires the full
   Design Gate chain: this record, the design doc, AI-2nd cross-domain review, human final approval
   before Rows 1+.
2. **SSOT by deletion, not by precedence flip.** Root `.env` owns every co-newbiz runtime value;
   `app/web-next/.env` retains only `DATABASE_URL` for the Prisma 7 CLI. The loader no-override
   rule stays exactly as it is.
3. **Drift guard, two severities.** env-check.ts: FAIL on same-key different-value across the two
   files, WARN on same-key same-value; boot: WARN only. One shared SSOT key inventory feeds both.
4. **Value-neutral migration.** Values copied as-is (including the S1-breaking
   `openai.com/gpt-6.1-terra` set — flagged as a separate decision); trailing spaces and the dead
   `CO_NEWBIZ_COMMITTEE_AGENTS` line removed as part of the same edit.

## Conditions

- The design doc carries a KNOWN/INFERRED/ASSUMED/UNKNOWN section; the UNKNOWN items (external
  cron/shell exports of these keys, .env.prod contents on this machine) must be checked at Row 1
  before the migration edits the files.
- The design doc's follow-up register includes the prisma.config.ts root-fallback that would let
  `app/web-next/.env` reach zero lines later.
