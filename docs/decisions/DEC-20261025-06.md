## Basis and limits

- **(a) Context SSOT relocation (ruling 1).** The workspace template (`templates/common/docs/variant.context.template.md`, workspace-level, outside this repo) and all 15 sibling projects (e.g. co-consult, co-news) place the variant context at `docs/<variant>.context.md`. co-newbiz's `docs/meta/` folder was created by the ADR-0108 documentation-surface restructure (commit `fe527873`, 2026-09-06) and `co-newbiz.context.md` was moved into it by commit `48082d1c` (2026-10-16); that placement is superseded by this ruling. The move is executed as `git mv docs/meta/co-newbiz.context.md docs/co-newbiz.context.md` with `docs/meta/` dissolved (index READMEs relocate to the docs root; the stale `VERSION_MANIFEST.md` stub is deleted — the generator writes the root-level file). The interim move left stale references: `docs/context.md` lines 6, 9, 72, 92 point at the old root path, which becomes correct again under this ruling; `docs/planning/product-backlog-roadmap.md:5`, `docs/governance/traceability-matrix.md:5`, and `docs/architecture/mcp-integration.md:5` point at the interim `docs/meta/` path and are retargeted. ADR-0108 keeps its historical text — the supersession is recorded here only, per the ADR-0174 precedent that an ADR is never rewritten and reversals live in the decision chain.
- **(b) Agent template standard (ruling 2).** `agents/README.md` already declared the Legal-Basis/Role/Protocols structure that the 39 stub files (28–29 lines: `## Role` plus boilerplate `## Scope`) do not honor. Sibling comparison data: 15 of 16 co-* projects average 108–230 lines per agent file against co-newbiz's 29, with sibling canonical files running the 9-section skeleton (design §3 fixes the section order, the four fixed `## Protocols` H3 subsections including the verbatim PM-ONLY INVOCATION refusal script, and the frontmatter contract: version 1.1.0, `role`/`color`/`description`/`examples`/`phases`/`handoff_to`/`handoff_from`/`required_skills` additions). Length bands: 4 domain leads 170–200 lines, 35 specialists 140–170 lines; reference exemplar `co-export/agents/fta-origin-analyst.md`. `agents/pm.md` (361 lines) and `agents/i18n-specialist.md` (157 lines) are out of scope — their bodies are untouched. No agent renames, additions, or deletions; flow.spec and procedures reference agent keys by name and are unchanged.
- **(c) Tier reconciliation direction (ruling 3).** The AGENTS.md roster carries the three agents as Medium; their definition files carried `tier: claude: high` (verified in git HEAD before this initiative), a divergence between the roster and three files. The roster is declared canonical by `agents/README.md`, and the tier SSOT ordering per the agent-lifecycle-manager skill runs roster → agent file → lifecycle record, so the three files (pmi-agent, commercial-dd-agent, technical-dd-agent) realign high→medium; the reverse (reconciling the roster to the files) was rejected. The lifecycle records mirror the file values. No other tier values change.
- **(d) required_skills directory-existence rule (ruling 4).** Agent frontmatter `required_skills` is the union of the SKILLS.md owner mapping and the flow.spec activity skills, restricted to skills with a physical `skills/<name>/` directory — registry rows without one are excluded. The SKILLS.md registry currently carries ~20 registered-but-missing rows, including all 22 technical-domain rows; populating `required_skills` from them regardless would create edges to nonexistent skills in the skill graph (`generate-skill-graph.ts`), so the union rule filters them out. The drift itself is dispositioned as a flagged follow-up (registry reconciliation is separately owned work), not silently absorbed into the rule and not blocking this initiative.
- **Limits.** This record governs the four rulings above and nothing else: no deal-pipeline stage gates, no flow.spec or procedures changes, no ADR historical-text edits (supersession of ADR-0108's placement lives here and in the design only), no edits to historical records (CHANGELOG, reports), and no change to the remaining 38 agents' tier values. QA for the initiative runs per design §7 (`agent:verify`, `validate-agents`, lifecycle audits, personas drift check, language gate); the three-stage review and human diff review on the /sync PR apply to the landed work as a whole.
