  every conclusion reads "결론: unresolved" and the discussion is
  internal-management-flavored instead of deal-substance. The v1 fix plan was
  rejected; the supplement meeting (2026-11-10) derived supplements A–G and
  the user approved revised plan v2 the same day.
- Root causes locked in code: brief-less convening
  (`committee-session.ts:423-427`, both web and pipeline paths omit
  `briefMd`); the minutes pass discards the topic (`committee-session.ts:308`);
  three stacked "unresolved" causes (bare enum in the `committee.minutes`
  prompt, silent fill at `committee-minutes-schema.ts:106`, and the fallback
  rule at `committee-chair.ts:245-286` keyed off `responds_to` tails that are

  (`CommitteeMinutesView.tsx:161`, `committee-scorecard.ts:229`); and the
  structural red-team rebut that makes any "one rebut ⇒ unresolved" rule
  guarantee permanent unresolved (`committee-agents.ts:145-158`).

## Determination

1. **Row 0 determination — update the existing spec.** The defects are
   completions of the registered design `2026-11-08-committee-minutes-as-meeting-design`
   (same subsystem, same ADR-0196 doctrine). The design doc gains a clearly
   dated amendment section (§8, 2026-11-10); no new spec; the registry id
   stays stable and `last_updated` is refreshed via spec-register.
2. **Semantic changes accepted** (supplements A–G, detailed in §8 of the
   amendment): default pre_fs brief injection at the single choke point
   `createCommitteeSession` (client briefMd wins; web + pipeline covered;
   `undefined` brief when artifacts are absent — convening proceeds, no
   fabrication); topic delivered to the minutes pass and folded into the
   input hash; the prompt convergence decision rule inside the existing
   5-section skeleton (codegen rerun mandatory, prompt version → @2);
   `degraded_resolutions` as a sibling meta key with the
   `resolveMinutesDraft` signature change; locale labels + degraded chip +
   open-questions badge using existing status-chip patterns;
   `computeMinutesFallback` kept byte-identical (explicit).
3. **Hash blast radius — documented as intended.** Adding the topic to the
   minutes input-hash parts means the recomputed `minutesInputHashFor` never
   matches any stored pre-amendment hash: every UNCONFIRMED stored session
   becomes regeneration-eligible; CONFIRMED sessions remain frozen because
   `minutes_already_confirmed` is checked before the hash comparison
   (`committee-session.ts:1129-1135`). No bulk regeneration will be run —
   fix-forward plus one reconvene validation on the target deal (supplement
   meeting action item 4); bulk regeneration would be a form-only improvement
   and violates the honesty rule.
4. **ADR-0196 amendment note (PM-approved process).** The semantic changes to
   committee session behavior (default brief, degraded meta, topic-in-hash)
   amend ADR-0196's operational reading. Per ADR-0061 the gate-moment ruling
   is THIS record; the ADR-0196 amendment note itself travels with §8 of the
   design doc and goes through PM approval before the implementation rows
   merge — the supplement meeting (process-governance-manager, platform-lead)
   confirmed this vehicle and that no `process/flow.spec.yaml` change is in
   scope: committee session mechanics are ADR-0196 product code, not
   procedure `agent_key` steps.
5. **flow.spec S4 verification (was UNVERIFIED in the meeting — now
   verified).** `process/flow.spec.yaml` S4 (lines 666-754):
   `entryCriteria: - S3 완료` is the ONLY entry criterion; the S1/S2/S3 items
   under `inputs:` are declared inputs (flow.spec v2.4.0 input-chain
   grounding), not enforced gates; S4's activities contain no committee
   activity (route-strategy / route-advisory / wacc-hurdle-confirmation /
   certification-screen / regulatory-screening; `gates: [screening, pre_fs]`).
   Consequence: "artifacts absent → brief omitted, convening proceeds" is
   aligned with the spec, not an exception to it; no spec-vs-implementation
   divergence is introduced.
6. **Human decisions carried forward** (supplement meeting action item 5,
   unchanged defaults): reconvene validation execution (default: yes) and
   final label wording (default: 합의 / 일부 합의 / 미합의(보류)). These remain
   owner calls; the amendment implements the defaults.
