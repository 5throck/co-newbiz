## Context

- User report 2026-11-04, dark mode only: a dropdown's popup background and
  text color are effectively identical — the selected item renders as a black
  block, the other options are invisible. Light mode is unaffected.
- `app/web-next/app/styles.css:279-296` styles `input, select, textarea`
  (`background: var(--input-bg); color: var(--fg)` at `:292-293`). Grep
  confirms no `option`/`optgroup` rules exist anywhere in the stylesheet; the
  only "option" rules are the custom `.agent-combobox-option` listbox
  (`:4442-4445`), which is token-paired and not a native select.
- Dark palette (`styles.css:167+`): `--input-bg: rgba(255,255,255,0.03)`
  (`:201`) composites to ≈ `#111317` over `--bg` `#0a0c10` (`:176`); `--fg:
  #eef0f4` (`:177`); `color-scheme: dark` IS declared (`:168`) — and the
  defect still occurs, which rules out propagation as the fix.
- This record, authored by the platform-lead as the technical AI-2nd seat, is
  Row 0 of the closure — design-gate activity only. No implementation file is
  modified by this ruling; the working tree carries the amendment to the
  registered design (§9 of `2026-10-09-ux-r2-design.md`) plus this record.

## Determination

- **Closed under the existing registered design, not a new doc**: the R2-C
  series of `2026-10-09-ux-r2-design.md` established the form-control token
  styling and the dark-contrast-at-token-level doctrine (§3c.1); a
  form-control token gap is a completion of that design, recorded as its §9
  (R2-G) amendment.
- **One global rule, both themes**: `select option, select optgroup {
  background-color: var(--surface); color: var(--fg); }` in `@layer base`,
  inserted directly after the `input, select, textarea` rule (`:295`), before
  the focus rule (`:297`) — element-selector base rules live in that layer
  per the `:231` comment (Tailwind preflight and utilities outrank them).
- **Pairing justified against the Onyx ≥ 4.5:1 rule in BOTH themes**
  (computed 2026-11-04, WCAG 2.1 relative luminance): dark `#171b22` vs
  `#eef0f4` = 15.1:1; light `#ffffff` vs `#171a21` = 17.4:1. `--surface` is
  the elevated-surface token — the popup is an elevated sheet, matching the
  `.agent-combobox` and notice-surface convention (§5 of the same design).
  `--fg` text, not `--muted-fg` (passes at 7.6:1 dark but needlessly dims
  items below the control's own text).
- **Checked/hover highlight stays UA-managed**: authoring `option:checked`
  is engine-inconsistent (Safari ignores most option styling; Chromium
  composites its accent highlight under author colors). With item colors
  authored, the UA highlight is a distinct accent row in both themes.
- **Explicitly untouched**: the custom `.agent-combobox-*` listbox
  (`:4436-4445`, already correct), ECharts, every other control. Disabled
  placeholder options keep UA dimming.
- **Scope**: the user did not name the screen; the fix is global for all
  native selects (30+ call sites). The design's §9.3 records the triage: the
  only custom listbox is verified correct, so a report persisting after this
  fix points to a different widget and becomes its own finding.
- **Row 1 (implementation) is a separate PM dispatch after user approval** —
  a mechanical paste of the rule text carried verbatim in the amendment.

## Consequences

- Every native select's popup renders authored `--fg` on `--surface` in both
  themes; the reported black-block/invisible-options failure is closed
  platform-agnostically, without depending on `color-scheme` propagation.
- Light mode gains an explicit authored item pairing (17.4:1) where it
  previously relied on UA defaults; the pairing is verified not to regress it.
- The verification bar is honestly manual: no unit or E2E assertion can
  render a native popup (browser chrome outside the DOM; axe/Playwright
  cannot see it). §9.4 defines the fails-before/passes-after protocol on
  three representative selects.
- Contrast checking of the new pair could later join `bun run
  contrast:check` (§3c.1 precedent), but the pair resolves to the existing
  audited `--surface`/`--fg` tokens, so no new pair enters the registry.
