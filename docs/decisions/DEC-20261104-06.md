## Determination

- **Not exempt**: three lib files across two stages, a guard-semantics
  change in two of them, and a change to how stored analyses are scored —
  no E1–E5 category applies (E3 hotfix-typo is the only code-capable
  exemption and this is a multi-file behavioral change).
- **Spec mapping**: A (zero-baseline guard, `market-sizing-pipeline.ts`) and
  B (unconditional `cagrPct / 100`, `synergy-pipeline.ts:440` +
  `synergy-rescore.ts:97`) → new design doc
  `2026-11-04-s1-sizing-cagr-unit-guard-design.md`, Spec NEW. C
  (`synergy-score.ts` market_attractiveness fail-closed guard) → dated
  amendment appended to `2026-10-18-synergy-4element-design.md`, which
  already governs the 5-factor methodology the change modifies.
- **Item A primary ruling**: fail-closed — when the parsed baseline rawTotal
  or the reconciled totalNow is 0, the analysis run terminates as
  `status: 'failed'` with an explanatory `error_message` (the mechanism the
  pipeline already uses, `market-sizing-pipeline.ts:443`), no matrix version
  is persisted, and downstream the industry simply does not join the
  completed-markets list S3 scores over. The uniform anchor-derived fallback
  to all cells is documented as the alternative and rejected as primary
  (fabrication concern, see alternatives).
- **Item B ruling**: unconditional `cagrPct / 100` at both sites, justified
  by the single-writer ×100 storage contract (KNOWN unbroken since
  2026-08-31), with a defensive range sanity rule — treat |fraction| > 1 as
  invalid input (exclude with a note) rather than scoring it — covering the
  ASSUMED-nil residual of contract-violating payloads.
- **Item C ruling**: non-positive (or null/non-finite) CAGR excludes the
  market_attractiveness factor with a missing-note instead of clamping to a
  fabricated 0/100, matching the fail-closed principle already stated in
  `synergy-score.ts:10-11`. Full design in the 4element amendment.
- Implementation (A, B, C) is a separate dispatch after user gate approval;
  Row 0 writes design + decision + spec registration only.

## Consequences

- After implementation, an all-zero LLM baseline can no longer reach the
  stored matrix: the degenerate `bottomUpCagr = -100` row class disappears
  at the source, and the -10000.0% synergy note becomes impossible —
  non-positive CAGR is either absent from stored matrices (A) or excluded
  from scoring with an honest note (B+C). This source-side elimination
  holds only for healthy-LLM runs: the offline/failed-LLM Wave C-3 (D-2)
  skeleton path ("offline or failed-LLM runs are deterministic
  placeholders", `market-sizing-pipeline.ts`) still persists all-zero
  matrices with `bottomUpCagr = -100` by contract, and those rows are
  covered at scoring time by the B+C exclusion, not at the source.
- Legitimately zero-growth markets (a real, verified 0% CAGR) are no longer
  scored 0/100 as "attractive-as-flat"; they are excluded from
  market_attractiveness with the missing-note and the remaining factors
  renormalize — this changes scores for any stored analysis with a
  non-positive CAGR (previously a 0-valued, fully-weighted factor diluted
  the weighted average; after the change it drops out and the score rises).
  The design records this as an intended behavior change, not a regression.
- Analyses whose LLM run degenerates will now surface as failed S1 runs
  instead of silently-completed garbage; the user retries via the existing
  re-run path (the DB evidence shows a re-run recovers the industry). This
  trades a visible failure for a silent wrong answer — deliberate.
- No schema change, no migration, no payload-shape change: the fix is
  control flow and arithmetic at three sites; stored legacy matrices score
  identically to today except for the non-positive-CAGR exclusion class.
- Out of scope, stated in the design: remediating the existing degenerate
  DB row (user-run S1 re-run, documented as remediation guidance only) and
  broader matrix numeric-quality validation beyond the zero-baseline case.
