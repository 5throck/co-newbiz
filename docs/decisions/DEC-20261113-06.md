## Context

User requirements (binding, PM-recorded 2026-11-13, from the Taeung case (company name romanized from the Korean source material)):

1. When external web search is FULLY blocked (all providers quota-exceeded or
   bot-blocked), the company profile pipeline must attempt a headless-Chrome
   search fallback before declaring degraded — using the established
   playwrightSearch pattern (CHROME_PATH + WEB_SEARCH_PLAYWRIGHT_ENABLED
   semantics, Tavily-432 → Playwright fallback precedent).
2. DART-grounded financial content must be REFLECTED and CLEARLY DISTINGUISHED
   from speculative content even when web search fails entirely. Verified real
   case (Taeung profile v3, 2026-11-13): DART succeeded (5 years, 40 accounts,
   corp code validated, report cross-check done) but the single degraded banner
   "No external search evidence (Tavily quota exceeded (432), Brave Search quota
   exceeded (429), DuckDuckGo bot-blocked)" (Korean copy, translated) covered the
   whole analysis, so the user read it as
   "DART lookup AND market research failed".

Verified code facts (working tree, 2026-11-13):

- `company-profile-pipeline.ts:405-414` calls `researchSourcesDetailed(queries, 12)`
  WITHOUT the playwright option; `:438-441` assembles `noResearchReason` from
  `providerFailureCauses(researchProviders)`; `:465` feeds step 3 only
  `DART financials: <year> financials, <n> accounts` (Korean copy, translated) — an account count, no values, so no
  SWOT item can be financially grounded today; `:516` merges
  `degraded = degraded ?? noResearchReason`; `:819-824` keeps the ADR-0132
  guard (LLM failure only) intact.
- The integrated fallback precedent exists:
  `capability-holding-check.ts:63-65` passes `{ playwright: true, deadlineAt }`
  into `researchSourcesDetailed`; `web-research.ts:425-429` runs the playwright
  provider only when everything before it found nothing, deadline- and
  circuit-breaker-aware; `web-research.ts:187-193` owns
  `WEB_SEARCH_PLAYWRIGHT_ENABLED` (default on, off under test without an
  override); `playwright-search.ts:24-35` owns CHROME_PATH.
- The brownfield route (`target-proposals/web-search/route.ts:242-273`) and
  `competitor-web-proposals.ts:161-180` carry the older manual pattern plus the
  provenance note "Web search quota was exceeded — evidence was secured via Playwright
  headless search; always verify the source URLs." (Korean copy, translated)
- `isNoResearchDegraded` (the no-search-evidence prefix — Korean copy, translated; the literal is pinned as NO_RESEARCH_DEGRADED_PREFIX in profile-degraded.ts),
  `profile-degraded.ts:8-18`) is consumed by `ProfileChips.tsx:11-13` (chip
  suppression when analyst evidence exists), `profile-analyst-edit.ts:237`
  (degraded clears when analyst adds evidence), and structural tests
  (`capability-ai-sources.test.ts:679-696`).
- `capability-holding-context.ts:51` classifies a profile as "researched" from
  `dataSources.webResearchCount > 0` — so headless-sourced profiles correctly
  become citable "[search-evidence-based]" (Korean copy, translated) downstream, matching the brownfield
  semantics.

## Basis

- Non-negotiable #4 (data confidence caps the RAG grade): DART-fed SWOT items
  are LLM inferences FROM verified disclosure data — they get a visible
  "financial-grounded" label (Korean copy, translated) and stay needs_judgement in the verification ledger; they
  are never presented as confirmed disclosure facts. The RAG cap stays amber in
  the degraded case (existing rationale text already says "Disclosure-based DART + qualitative items are unverified AI estimates
  without search evidence" — Korean copy, translated).
- Boundary #2 (a person decides): the profile remains a proposal; no gate or
  verdict changes; the headless-sourced profile flips nothing automatic except
  the honest sourcing classification it earns by having real URLs.
- ADR-0172 amendment (3) owns the degraded-profile semantics this ruling
  extends: the `degraded` field is the sanctioned carrier and stored historical
  profiles are never rewritten.
- ADR-0098: the design doc separates KNOWN / INFERRED / ASSUMED / UNKNOWN and
  leads with conclusions.

## Determination (design decisions ruled)

- **D-A** Fallback integration: chain-integrated — step 2 passes
  `{ playwright: true, deadlineAt: Date.now() + 30_000, playwrightQueries: 2 }`;
  headless sources enter the SAME `research` flow (researchSources payload,
  citations, webResearchCount, holding-check classification). Provenance:
  `dataSources.webResearchPlaywright?: boolean` plus a step-2 summary note and
  a provenance chip, adapted from the brownfield searchNote wording.
- **D-B** Degraded split: keep the string carrier and the
  the no-search-evidence prefix (Korean copy, translated); `noResearchDegradedReason` gains an optional
  dart parameter and, when DART succeeded, states the success inline
  (Korean copy, translated: "DART financials retrieved successfully (years, N accounts): the financial analysis is disclosure-based; only the qualitative items are AI estimates"));
  `degradedChip`/`DegradedChip` gain an optional dartGrounded input for the
  short label. No payload type change.
- **D-C** Per-item grounding: step 3 receives a compact deterministic financial
  block (years, revenue/profit, key ratios) and returns per-item
  `basis: financial|estimate`; normalized additively into
  `itemBasis?: {strengths, weaknesses, opportunities, threats}` on the payload;
  the UI renders a "financial-grounded" chip (Korean copy, translated) per item (en+ko locale keys); analyst edits clear
  the edited index's basis; ledger entries keep needs_judgement but the
  evidence text names the financial grounding.
- **D-D** Unchanged: step 1 DART flow, step 5 cross-check, ADR-0132 guard, RAG
  cap structure, append-only versioning, schemaVersion 3 (all additions
  optional), both brownfield/holding-check routes.
