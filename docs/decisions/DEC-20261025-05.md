## Approver

- **Approved by**: user (account techcross) — structural ruling issued on reviewing the shipped prompts (2026-10-25): the prompt skeleton's `# Role` forcibly overrides the agent's real charter, capability gaps belong in agent definitions (or new agents/skills), and forcing execution-style roles onto the pm agent despite its never-execute principle is a serious structural defect. Design response drafted by platform-lead on PM dispatch as the Design Gate amendment (design work only — implementation is dispatched separately), 2026-10-25. No gate verdict on the deal pipeline changes under this record.

## Basis and limits

- **(a) Verified basis.** Identity injection paths were verified in the original design (§5.3 table): the free-query route injects entry name/role (`app/web-next/app/api/agents/query/route.ts:79-82`), the committee path injects agentKey (`app/web-next/lib/committee-llm.ts:60-66`), and the prompts.json lane sends `systemMessage(key)` verbatim with no injection (`app/web-next/lib/prompts.ts:14-16`) — so a prompt claiming "You are an X" was the only identity source for stage-artifact calls, which is the override the user ruled on. Roster roles live in `agents/*.md`; the runtime does not inject full definitions into stage-artifact calls, and this record decides NOT to add such injection. Machine bar v2.0.0 (`scripts/co-newbiz/generate-prompt-registry.ts`) pins `SECTION_MARKERS` including `# Role`; all 40 prompts carry it (verified 2026-10-25), and role sentences exist only inside `# Role` sections. Exactly 2 prompts have `agent: null` (`s8.business_case_prose`, `committee.position`).
- **(b) Skeleton.** 5-section skeleton confirmed (markers in order: # Evidence boundary / # Task / # Output contract / # Language / # Proposal-only disclaimer — the last omittable only for the gate-unlinked set). Functional stance moves into task instructions; "who does this" remains the `agent` field → catalog → `promptAgent()` AgentCallMeta single truth (§5.3, strengthened from "no roster identity claims" to "no role assignment at all"). The rejected `# Task framing` and persona-injection alternatives are recorded above.
- **(c) Enforcement.** Machine bar v2.0.0 → v2.1.0: `SECTION_MARKERS` drops `# Role`; NEW hard rule — a closed heading vocabulary (`/^#\s+\S/` lines outside the 5 markers die as "undeclared section marker"), blocking `# Role` reintroduction and any rogue persona heading; header doc block and `@version` updated; all sets (`GATE_UNLINKED`, `PROSE_OUTPUT`, `STYLE_EXEMPT`, `JSON_OUTPUT`), Hangul zones, ONE-JSON/Explanation-style checks, and the advisory warn channel unchanged. Because v2.1.0 dies on the current 40 prompts, the generator change and the 40-prompt migration land atomically in one PR.
- **(d) Capability audit.** The implementation row executes the §13.3 procedure over all 40 prompts: extract the task verb-object from `# Task` + `purpose`, anchor on `agents/<agent>.md` (+ SKILLS.md `owner:` reverse lookup), classify covered / addition / escalation with mandatory charter citations (a row without a citation is invalid). Additions are one-sentence charter additions applied via `bun run agent:verify` + roster regeneration; escalations go to PM under ADR-0080 (hiring signal or skill request approval) and nothing is auto-created. Special rows: the two pm keys additionally pass the PM-nativeness test; `s11.integrated_insight` audits against process-governance-manager's charter (dual-assignment perspective owner, §3.3); `committee.position` is exempt from charter matching (runtime-per-member attribution); `s8.business_case_prose` anchors on the flow.spec activity owning the interpreted output, else escalates (null agent = missing charter anchor = attribution-defect candidate). The audit never re-attributes prompts itself — attribution is D1-closed territory and moves only by PM decision record.
- **(e) PM closure.** pm-attributed prompts are a closed set of exactly `pm.query_classify` (triage/routing — PM-native per agents/pm.md "classify requests, dispatch specialist agents"; ADR-0078) and `pm.flow_suggest` (decision-support proposal drafting — ADR-0080/0061; proposal-only). Both lose their personas ("query classifier", "flow coordinator") with no replacement. Future pm-attributed prompts require a DEC establishing nativeness at Design Gate, else are re-attributed to a specialist or a new agent; the persona patch is forbidden; and the charter-addition path is unavailable to pm — agents/pm.md's non-execution scope is normative.
- **Limits.** This record changes design documents only — no code, no prompts.json, no agents/*.md in this row; implementation is a separate dispatch. Runtime injection paths, the 40 `purpose` fields, `DUAL_ASSIGNMENTS`, `SPECIALIST_TRACK_AFFINITY`, flow.spec.yaml, JSON output contracts (§5.5 byte-compatibility), Korean output pinning (i18n design §4), proposal-only disclaimers, and the ADR-0098 two-way communication principles (design addendum §A) are unchanged. §5.1, §5.3, §5.4's Role-column requirements, and §A-2's 6-section-vocabulary rationale are superseded where they conflict with design addendum §13 (append-only precedence). The question of injecting real agent charters into committee role-play is explicitly left as a separate future Design Gate question.
