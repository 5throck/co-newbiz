## Context

- Trigger: user report 2026-11-24 — selecting S8 `사업성 분석` first shows the `재무적 타당성`
  tab, then moves to `개요`.
- Cause (verified by PM): the 2026-11-23 remediation made bare `/projects/{id}/business-case`
  redirect to `/projects/{id}` via a client-side `useEffect` in `BusinessCaseStage.tsx`
  (`s8BareTabRedirect`). The effect runs after the first render, and `resolveS8Tab(null)` returns
  `"overview"`, the financial sub-tab key under `재무적 타당성`, so that tab paints for one frame.
  Every S8 entry link still targets the bare route (`StageFrame.tsx:39` `STAGE_HREF.S8`,
  `projects/page.tsx:141`, `deals/[id]/[stage]/page.tsx:331` `PROJECT_STAGE_PATH.S8`), so the
  fallback is exercised on every normal click; a `/deals/{id}/s8` entry makes three hops.
- Dispatch: Design Gate Row 0, ux-designer-agent drafted the amendment; PM rules (this record).

## Basis

Governing rules cited in prose (no registered rule ids): ADR-0061 (gate rulings recorded before
dispatch continues); the Design Gate (ADR-0074) — a link-target and redirect-timing change on an
existing screen is a code-adjacent change and carries a spec amendment; the 2026-11-23 ruling
(DEC-20261123-01 and the design doc's "Defect Remediation — 2026-11-23" section), which this
record tightens without reversing: the OUTCOME (absent `?tab=` lands on 개요) stands, the
mechanism and entry points change. Not superseding: DEC-20261123-01 stays `accepted`.

## Determination

1. **Entry links.** Every S8 entry link with no explicit tab targets `/projects/{id}`:
   StageFrame S8 (stage rail), the projects-list shortcut, and the deal-stage S8 entry.
   `ProjectStageTab`: S8 with an empty query goes to `/projects/{pid}`; S8 with a query keeps
   `/projects/{pid}/business-case?{query}`.
2. **Bare-route fallback.** For bookmarks and typed URLs the redirect must complete before the
   stage renders. The ruling is on the outcome — `BusinessCaseStage` is never committed to the DOM
   for a bare URL. Permitted mechanisms: a server component reading `searchParams` and calling
   `redirect()`, a `next.config` redirect with a `missing` query condition on `tab`, or a client
   wrapper that renders nothing while the replace is pending. Render-then-redirect in an effect is
   the defect. The redirect keys on the ABSENT `tab` param, not on the resolved value.
3. **Unchanged.** Explicit `?tab=` values (including `?tab=overview`, which still opens the
   financial lens `설명·생성·권고`), embedded mode (`urlSync=false`), and the greenfield
   `?tab=targets` normalization resolve exactly as before.
4. **Verification.** A new unit test asserts the S8 entry hrefs (StageFrame S8, projects list,
   deal-stage S8 path with empty query) equal `/projects/{id}`; the existing `s8-goals-ui` test for
   `s8BareTabRedirect` keeps passing; a browser check confirms clicking S8 in the stage rail shows
   `개요` with no intermediate `재무적 타당성` paint.
