## Context

- The S1 growth-gap calibration loop (design `2026-09-18-s1-growth-gap-calibration`, v1.2.0) has
  run in production with three structural issues the user ruled on 2026-11-13 (all three verified
  against the working tree before this ruling):
  1. The proposal trigger (`CALIBRATION_TRIGGER_PCT = 20`, `market-calibration.ts:12`) and the
     convergence goal line (`CONVERGENCE_TARGET_PCT = 15`, `calibration-sweep.ts:21`) disagree —
     in the 15–20% band the loop presents "below trigger" (green) while its own feasibility line
     says not converged.
  2. The deterministic-scaling escalation (design `2026-09-20-calibration-escalation`, implemented)
     exits the loop by adopting `external × 0.85`, pinning the residual gap at exactly 15.0% —
     it cannot satisfy a "< 15%" goal and it erases the independent bottom-up estimate. One
     historical row exists (drone, 2026-11-12). The predecessor "persistent escalation" direction
     was cancelled before any artifact; nothing in `docs/specs` supersedes (verified by grep).
  3. Top-down reference visibility has three verified defects: reference details render only
     inside CalibrationPanel; a superseded reference leaves the displayed version's consensus
     silently stale (the real drone case: reference superseded 2026-11-13 01:22, v4 created 01:20
     still shows topDown 14% with no signal); and `resolveTopDownConsensus`
     (`market-sizing-pipeline.ts:397`) labels every recorded reference — including auto-saved
     `llm_prior` rows — "person-recorded external reference" (Korean copy, translated), with
     `source.origin` hardcoded `"user"` at
     `:399`.
- PM dispatched this Row 0 with the three user decisions as binding requirements; every file:line
  claim in the dispatch brief was re-verified by the dispatched agent on 2026-11-13.

## Determination

1. **Row 0: non-exempt.** Goal-semantics change on the loop's trigger, a multi-surface feature
   removal with API contract breaks, and a payload-shape addition are architectural; the full
   Design Gate chain applies. Design of record registered as draft.
2. **Decisions 1–3 adopted verbatim** as binding requirements; the trigger aligns to the goal
   line (one gap, one line), the escalation is removed without a deprecation shim and without a
   destructive migration, and the three reference-visibility defects get the minimal coherent
   fixes specified in the design doc (§3a–c).
3. **Supersession chain:** design `2026-09-20-calibration-escalation` is marked superseded by the
   new design's frontmatter (that doc itself is not edited); the cancelled persistent-escalation
   direction is recorded as superseded by this removal decision here, same day — it left no
   artifact to mark.

## Conditions

- Implementation follows the design doc's touched-files and test plan; the PR body must state the
  API contract breaks (POST escalate removed; `escalated_cagr_pct` / `escalatedCagrPct` removed
