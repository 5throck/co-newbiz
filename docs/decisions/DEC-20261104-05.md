## Context

- The PM verified on 2026-11-04 (direct OpenDART calls, code reads) that
  `fetchFinancials` (`app/web-next/lib/dart-client.ts:477-538`, line numbers
  current at `64e0dd7a`) implements a window-level CFS→BFS fallback while its
  JSDoc (line 487) promises per-year fallback: `anyFound` is set if any year
  returns data under CFS and line 532 breaks before BFS is tried, so years
  answering status `013` under CFS are silently lost.
- Live case: (`주`)`수산아이앤티` (corp_code 00577016, stock 050960, KOSDAQ) —
  CFS 2023 → 000 (144 items), CFS 2024/2025 → 013; OFS 2023 → 96 items,
  2024 → 144 items (`매출` 26,671,468,809 KRW), 2025 → 141 items (`매출`
  30,711,816,841 KRW). `사업보고서` filings continue through 2026-03-23; from
  FY2024 the company submits `개별재무제표` only. UI shows financials to FY2023.
- Second user requirement: each year's data provenance (`연결`/`개별`) must be
  visible on screen. Today no render site shows it — `fsDivLabel` is declared
  in `components/stages/synergy/types.ts:8` but never rendered, and the
  BFS-note in `company-financials.ts:125` fires only when CFS failed for all
  years, so the partial-CFS case shows no provenance at all.
- This record is Row 0 of a new Design Gate cycle: design authoring only. No
  implementation file is modified; the working tree gains the new design doc
  and this record. Spec registration is deferred to Row 4 per the PM's plan.
- Registry check: `grep -i dart docs/specs/registry.json` → 0 hits, so the
  design is filed as **Spec NEW**, not an amendment to a registered design.

## Determination

- **Spec NEW, not exempt**: the defect closure restructures fetch control
  flow and changes a payload shape consumed by three pipelines and two render
  sites — no E1–E5 category applies (E3 hotfix-typo is the only code-capable
  exemption, and this is a multi-file behavioral change).
- **Per-year fallback, one basis per year** (design §2.1): CFS first per
  year, BFS for that same year on miss; a `000` response with zero
  WANTED_ACCOUNTS matches counts as a miss (the edge the current loop never
  re-tries). CFS wins when both bases yield for a year; the per-account
  first-wins dedup inside a block is unchanged.
- **Provenance payload** (design §2.2): `items[].fsDiv` canonical (both
  render sites already iterate `items`), `yearly[].fsDiv` stamped alongside
  (the persistence consumer's shape), aggregate `fsDiv: "CFS" | "BFS" |
  "mixed"` computed once at loop end; `fsDivLabel` stays a persisted Korean
  product string while the UI renders its own i18n strings from the enum.
- **No `fact_financial` schema change** (design §2.3): retrieval metadata is
  not a fact attribute; in-index `fs_div` forks canonical facts, an attribute
  column costs migration + null handling with no consumer. The user-visible
  audit surface is the profile JSON payload, which persists the new fields
  wholesale (`company-profile-pipeline.ts:557`).
- **UI pattern** (design §2.5): year column headers and ECharts legend names
  suffixed from an `fsDivByYear` map — "2024 (`개별`)" — plus one visible
  mixed-source caption line; text-based, not color-only; legacy payloads
  without `fsDiv` degrade to bare year headers. Two render sites total
  (`ProfileFinancialsTab.tsx`, `TargetDataTabs.tsx`) — grep-verified there is
  no third; the synergy tab needs type widening only.
- **Row 1 / Row 2 are separate dispatches after user approval**; Row 0 writes
  design + decision only.

## Consequences

- Mixed-basis companies (`개별`-only from some fiscal year) recover their
  missing years in the UI, in `fact_financial` (corrected years flow through
  the existing sync), and in the profile coverage note — which stops
  factually claiming "`이후 사업보고서 미제출`" for individual-only filers
  because `yearsFound` extends to the recovered years.
- Worst-case OpenDART calls double (10 for `years: 5`) but only for CFS-missing
  companies, against `DAILY_BUDGET = 15_000`; pure-CFS companies are unchanged.
- All new payload fields are optional, so stored legacy payloads, the
  `synergy/types.ts` shape, and existing test fixtures remain valid;
  `company-financials.ts`'s `fsDiv === "BFS"` comparisons survive the union
  widening.
- §4 of the design sets the fails-before/passes-after bar: the T1 mixed-window
  test (and the manual `수산아이앤티` check) must fail on the current loop and
  pass after Row 1.
