## Context

- `db/migrations/0185_notification_delivery.sql` is tagged `@reversible: false` in its own header (it rebuilds `notification` to widen the `trigger_type` CHECK and add `title`/`source_ref`; SQLite cannot alter a CHECK in place). Its header requires a pre-migration backup and joint dba + release-engineer sign-off (FR-OPS-02, ADR-0014) before it runs against any non-scratch database.
- The dba pre-apply procedure (dba dispatch under PM, 2026-10-31) stopped at the safety check: the dev web server held `db/data/co-newbiz.sqlite` open. The owner then directed Option A: take the backup and record the sign-off now; keep the dev server running; defer the migration to the next dev-server restart.
- Release-engineer review of the migration itself was performed during the P2 runbook task and its QA gate (the review that produced the migration header's rollback-limits text); this record supplies the second required role of the FR-OPS-02 pair, per that prior review.

## Deferred application — sanctioned resume procedure

The migration 0185 apply is authorized **only** as the following single window, at the next dev-server restart:

1. Stop the dev web server (`bun run dev` / `next dev -p 7748`; PIDs observed 2026-10-31: 12992–12995).
2. Apply: `bun run db:migrate` (=`bun scripts/co-newbiz/newbiz.ts db:migrate`).
3. Verify 0185 schema: tables `notification_delivery`, `notification_recipient_policy`, `user_notification_pref`, `notify_webhook_target` exist; `notification` has `title` and `source_ref` columns; `app_user` has `email`; `SELECT COUNT(*) FROM notification_recipient_policy` = 10 (D9 seed rows).
4. Re-seed: `CO_NEWBIZ_SCHEDULER_ENV=dev bun scripts/co-newbiz/schedule-seed.ts` — expect `existing: ["gate_integrity.shadow_report","watch.evaluate"]` and `inserted: ["notify.deliver","notify.digest"]` (all created disabled).
5. Restart the dev server; confirm the tick heartbeat stays fresh and the launchd last exit code stays 0.
