## Context

- A user on dev opened `/deals/{id}/s5` on a brownfield deal: the Greenfield entry-strategy form
  rendered, the save failed with 409 `not_applicable_track`, while `/deals/{id}/s4` showed the
  current decision as brownfield. PM dispatched this Row 0 under the Design Gate (ADR-0074) after
  the root cause was verified in code (design §2, with file:line).
- The trigger is a **concurrent-session conflict**: ADR-0124 deliberately allows an analyst to keep
  an S4 draft open across sessions (upsert per opportunity), and the draft save stamps
  `decided_at = now` with `status='draft'` (`route-decision/draft/route.ts:64-68`). When that draft
  is saved after the final decision exists, the unfiltered convention query in
  `latestRouteDecision` (`process-flow.ts:394`) returns the draft, and the process view's track —
  the input to `TrackGate` — is poisoned. The same user (or a second session) can then render the
  wrong track's S5 form while the save guard, which reads `is_current = 1`
  (`greenfield/[oppId]/route.ts:91-96`), refuses with 409. Render gate and save guard must read the
  same row; today they do not.
- The system already carries the authority model this ruling applies: migration 0101
  (`db/migrations/0101_route_decision_current.sql`) backfills exactly one `is_current = 1` row per
  opportunity, enforces at-most-one with a partial unique index, and its header comment warns in
  terms that describe this defect verbatim — convention queries like
  `ORDER BY decided_at DESC LIMIT 1` "can quietly read a stale decision", and gate/stage logic must
  read the `is_current=1` row as authority. `latestRouteDecision` is the leftover convention query
  that predates 0101 and was never migrated onto the flag.

## Determination

1. **Spec: NEW id, no exemption.** Ruled a new spec `2026-11-11-route-decision-current-authority-design`
   under ADR-0074 — no E1–E5 exemption, because the change alters the semantics of a shared read
   consumed by seven call sites across the process engine, gate ladder, gate snapshot, and IC
   package (a defect fix with behavioral blast radius, not a trivial edit).
2. **The fix: one function, authority row.** `latestRouteDecision` reads
   `WHERE opportunity_id = ? AND is_current = 1 LIMIT 1`; signature, return type, and export
   unchanged; no schema migration, no data migration. Design §3 records the caller-by-caller
   expected behavior shift; every shift is toward ADR-0124's rule that a draft is not a decision.
3. **Reader boundaries.** `getDraftRouteDecision`, `listRouteDecisionsWithScores`, the S5 save
   guard, and `resolveTrack` are intentionally unchanged — the last two are already on the
   authority definition and are the half of the disagreement that was right.
4. **Test obligation.** Rows 1+ must land `tests/unit/route-decision-current-authority.test.ts`
   pinning: draft-newer-than-final returns the final's track; draft-only returns undefined;
   superseded final returns undefined; fixtures prefer `finalizeRouteDecisionCurrency`. The
   implementer must run the process/route/gate/greenfield/brownfield suites — fixtures that insert
   `route_decision` rows without `is_current` now read as "no decision" and may need repair (design
   §5 names the two known un-flagged seeders: `migration-0073.test.ts`, `project-delete.test.ts`).
5. **Consequence.** The three live definitions of "current decision" (§2.2 of the design: history
   list is_current-first, process engine latest-decided_at, authority is_current=1) converge on one
   authority definition. TrackGate, the S5 save guard, `resolveTrack`, the ladder, the snapshot,
   and the stage predicates all read the same row; the draft/final UX of ADR-0124 keeps working
   exactly as designed, and a draft can never again decide a track, complete a stage, select a gate
   ladder, or point kill-procedures at the wrong track.
