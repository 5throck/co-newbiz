## Context

S1's calibration loop (design 2026-09-18-s1-growth-gap-calibration) produces
human-accepted growth drivers with numeric CAGR contributions in
`industry_driver_calibration` (driver, direction, impact_pct, rationale,
status='accepted', decided_by/at). They are person-vetted but LLM-estimated
signals. The pipe exists: `GET /api/market-overview/insights`
(`app/web-next/app/api/market-overview/insights/route.ts:109-118`) exposes
per-industry `calibration` (triggered, our/external CAGR, gap,
applied_drivers) — and zero S2 code consumes it (grep-verified 2026-11-13:
no calibration/applied_drivers references in `lib/entry-market*.ts`,
`lib/opportunity*.ts`, `components/EntryMarketFlow.tsx`,
`components/EntryMarketDerivationPanel.tsx`; `OpportunityFunnelStage.tsx`
calls the endpoint at line 239 but its local `SizingInsight` type at lines
64-83 omits `calibration`).

User requirements (binding, PM-recorded 2026-11-13):

1. S2 opportunity discovery must SEE S1-validated drivers as linked signals,
   closing the S1⇄S2 loop (S2's curated demand edges already feed S1 sizing
   via ADR-0129; drivers flowing back completes the circle).
2. Signal exposure + analyst promotion ONLY — no auto-generated
   opportunities, no automatic score inflation. A human attaches/promotes a
   driver into an opportunity candidate.
3. Provenance discipline: driver-derived opportunity evidence links the
   driver ROW ID; drivers stay C-grade quantitative authority — human
   acceptance does NOT upgrade LLM-estimated ±%p.
4. Purpose asymmetry guard: S1 drivers explain why our number differs from
   external; they are NOT automatically entry opportunities. Company-fit
   filtering stays S2's own logic.
