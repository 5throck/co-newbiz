## Basis

- **(a) The four sites are one observation, three truths.** Stage-level `applicableTracks` (both-tracks) with a track-specialist `agent` on an activity is the surface fact at all four sites, but the governance meaning differs: #1 and #2 are genuine specialist lenses over genuinely shared artifacts (the sketch serves both tracks until the route is known; deal-shape evaluation serves both tracks as the comparison frame); #3 is exclusive scoping already carried by the procedure list; #4 is a documented divergence between the activity-field owner and the per-track effective owner (Q6). A ruling must therefore both keep the assignments (they are semantically right, and in #4's case user-pinned) and give the console a way to state which truth each site carries.
- **(b) Spec discipline.** flow.spec.yaml v2.10.1 is unchanged by this ruling except for the comment-only insertions of addendum §11.5 (comments are not parsed by generators or asserted by tests — no `meta.version` bump, no regeneration, no mirrors-spec impact). Activity-level `applicableTracks` remains unsupported (ADR-0161 decision 5, v2.8.0 comment :71-72, v2.7.0 comment :86-88): stage-level routing and procedure `applies_when` stay the only scoping forces.
- **(c) The G mechanism — boundaries.** `SPECIALIST_TRACK_AFFINITY` lives in `generate-pm-catalog.ts` beside `DUAL_ASSIGNMENTS` (same pattern: rationale mandatory, generator die-validation, projection into the generated catalog, exact-set test) and is exported from `pm-catalog.generated.ts`; GET /api/flows maps it into the `specialistMarkers` data (kind + note added to the existing prop contract, additive). It carries no applicability, no predicate, no routing key — it cannot affect dispatch, filters, or gates; set changes require a gate-moment decision record. Full design: design doc addendum §11.3–§11.4.
- **(d) Verified facts the ruling rests on**: the S2 sketch route serves every opportunity without a track gate and its header names the greenfield-agent activity (sketch/route.ts:1-3); prompts.json pairs `opportunity.sketch` with greenfield-agent (no D1 divergence); entity-ic-review step 3.1 exists as documented (applies_when case_type=greenfield, agent_key greenfield-agent, financing-agent co-review — schema.yaml:47-55); the test suite locks both S9 capability-dd and S11 investment-structuring assignments with Q6 annotations (process-flow.test.ts:123-132, :151-154).
- **Limits.** This record does not change any activity assignment, does not alter routing or procedure scoping, does not touch prompts.json, generators, tests, or UI code (the mechanism design is specified for the implementation rows), and does not reopen ADR-0161 Q6 or any other user decision. The flow.spec comment insertions of §11.5 are documentation, to be applied by the implementation row as written.
