## Context

Verified loop pathology (live drone-industry run 2026-11-14, deal
01M6ZPEZ39R78DW612ECEXY5W4, quoted in the PM dispatch): the S1 calibration
loop's attribution-proposal generator re-proposes semantic duplicates of
already-accepted drivers under slightly different names — v11 proposed three
paraphrases (regulatory-environment improvement / technology-driven operating
cost reduction / commercial drone demand expansion — Korean copy, translated),
the person accepted all three, and v12 immediately proposed three MORE
paraphrases, one byte-identical to an accepted driver. The attribution prompt
(market-sizing-pipeline.ts:1420-1423) never sees the accepted names and
nothing filters the output.

Consequence: the accepted-driver impact sum grew to +12.0pp against a needed
uplift of +3.9pp, the run-start Monte-Carlo sweep (`sweepCombinations`,
calibration-sweep.ts:92-154, v1 plausibility filter = summed impact > 2x
needed uplift excluded, :105/:121) reported feasible_ratio 0.0, and the loop
cannot converge while the set is over-cap. Two related design gaps: the
leave-one-out exclusion proposal (market-sizing-pipeline.ts:1746-1803,
amendment 2026-11-13b) fires ONLY on gap worsening beyond
EXCLUSION_NOISE_BAND_PCT — the overshoot case has no path — and even inside
the block, `rankExclusionCandidates` output is only used when
`top.improvementPct > 0`, which is impossible under multi-culprit overshoot
where every removal still leaves feasible_ratio 0.

Verified code facts (worktree, 2026-11-14):

- `pendingDriverProposals` is filled only by the step 5-C attribution block
  (:1417-1441); within-batch dedupe is exact-string only (`seenDrivers`,

## Determination (design decisions ruled)

- **D-A** Prompt block (market-sizing-pipeline.ts): the attribution
  instruction gains the accepted-names advisory block
  (`ACCEPTED_DRIVERS_PROMPT_CAP = 20`, mirror of the ignore-hint cap); the
  gap-analysis prompt is untouched.
- **D-B** Hard filter: `driverKey` + `NAME_SIMILARITY_JACCARD_THRESHOLD`
  (0.6, consumed by the unchanged-behavior `isSimilar`) +
  `filterDuplicateDriverProposals` in name-similarity.ts; the pipeline filters
  after within-batch validation, before insert, preserves the 5-cap, and
  states the drop count in the step-5-C summary.
- **D-C** Overshoot signal: `PLAUSIBILITY_CAP_MULTIPLE = 2` shared by
  `sweepCombinations` and the new pure `buildOvershootSignal`;
  `matrix.calibration.overshoot?` (additive optional, CAGR-anchor-only,
  `feasibleRatio: number | null` honest-absence when no run-start sweep ran);
  CalibrationPanel renders one muted `role="status"` line with the sum/needed
  /cap numbers; ko+en locale keys.
- **D-D** Exclusion arm: `selectExclusionArm` pure selector; outer trigger
  widens to `worsening || overshoot` where the overshoot side additionally
  requires `calibration.triggered === true` (unconverged only — AC-15 arm 1
  keeps its meaning); the overshoot arm fires only when
  `baselineFeasibleRatio === 0` AND `top.improvementPct > 0`, with rationale
  stating the set is over-cap and that removing this one driver brings
  goal-reaching combinations back (the Korean recommendation sentence, per
  dispatch); worsening arm takes precedence, byte-identical.
