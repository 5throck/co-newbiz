## Basis and limits

- **(a) Audit basis.** The 7 divergences, the 4 track-specialist-in-common-stage sites, the 34/40 Korean prompts, and the 50–1005-char quality spread are PM-verified audit facts (2026-10-25); spot-checks against the SSOTs confirmed all of them (`process/flow.spec.yaml` v2.10.1, `app/web-next/prompts/prompts.json`, `scripts/co-newbiz/generate-pm-catalog.ts`, `tests/unit/pm-catalog.test.ts` — the test that currently permits divergence via its "보조 관점" comment is the governance gap this ruling closes).
- **(b) Default rule.** flow.spec wins: a prompt mapped to an activity is attributed to the activity's agent unless the pair is a documented dual assignment. Directions used: (i) prompts.json fix — items 1, 3, 4, 5, 6, 7; (iii) documented dual assignment — item 2 only. Direction (ii) (flow.spec amendment) was used zero times, so this decision touches no process SSOT and no spec version bump.
- **(c) Enforcement.** Hard fail in `generate-pm-catalog.ts` (die on prompt.agentKey ≠ activity agent unless the pair is in `dualAssignments` with a non-empty rationale), projected into the generated catalog and asserted by new pm-catalog.test.ts cases ("exactly the documented set"). New exceptions require a gate-moment record — the list does not grow silently.
- **(d) Prompt standard.** All prompts.json `system` entries move to a 6-section skeleton (# Role / # Evidence boundary / # Task / # Output contract / # Language / # Proposal-only disclaimer — the last omittable only for gate-unlinked prompts). Instructions in English; Hangul permitted only in # Language and # Output-contract value examples (machine-checkable in generate-prompt-registry.ts); response language pinned to Korean per the i18n §4 boundary; roster identity claims removed from prose; JSON contracts byte-compatible (per-key consumer file:line verification required in each rewrite PR); the five thinnest prompts (company_profile.competitive, s4.synergy_ic, s4.synergy_fa, s4.synergy_synergy, company_profile.crosscheck) are enumerated for full rewrite. committee.position keeps its documented topic-language exception. ADR-0098 output-side rules (§2.2/§2.3/§2.5/§2.6 instruction structure; §4/§5/§6/§7 output side) are cited per skeleton section in the design.
- **(e) Visualization.** SPEC_STAGES gains `name` + `applicableTracks` (generate-spec-activities.ts + SpecStage type + regenerate); GET /api/flows replaces the PM_CATALOG trackScope-union derivation with the direct projection; the flows client's hard-coded STAGE_NAME_KEY map is replaced by keys derived from the served stage ids while display labels remain i18n catalog keys. The blueprint tab gains a pure-SVG stage-flow graph reusing the docs/wiki/ko/Home.md journey-map geometry (CSS-variable colors, role="img" + Korean <title>, no new dependencies), stage nodes with per-activity domain-colored dots, click → existing setSelectedStage drill-down (no new state), and a WCAG-conformant specialist-in-common-stage marker whose data source is deliberately left as an open interface pending Row 4 (guards → per-activity flags; status quo → deterministic derivation).
- **Limits.** This record does not decide Row 4 (track scoping of activities), does not translate the 40 `purpose` fields, does not change flow.spec.yaml, and does not add activity mappings for currently unmapped prompts (e.g. s8.business_case_adoption). Implementation is authorized for Rows 1–3 under the registered spec; the rewrite sequence runs through the dry-run lane with the proposal-package → PR path as the only permanent landing route (2026-09-15 spec §6.6/§6.7 invariants).
- **Amendment (2026-10-25, same day): communication-principles mandate.** The user issued a workspace-level mandate — "The AI Workspace shall use two complementary communication principles: Human → LLM: ASD-STE100-inspired controlled language; LLM → Human: 3Blue1Brown-inspired intuitive explanation" (a verbatim restatement of ADR-0098 §1). Ruling recorded as the dated Addendum in the design doc (§A-1–A-5): (1) ASD-STE100 governed language applies to ALL skeleton instruction prose as a first-class element; prompts.json becomes the first artifact class under a machine guard for controlled language (it sits outside validate-md-language's md/yaml scope — the design closes that gap conceptually); the hard machine bar stays at section markers + Hangul allowed zones + ONE-JSON wording, extended only by the Explanation-style clause presence check, and sentence-structure linting is ruled ADVISORY (warn-only heuristic) per the ADR-0079/ADR-0098 advisory enforcement model. (2) The intuitive-explanation style lives as an `Explanation style` sub-clause inside `# Output contract` — not a 7th section — preserving the recorded 6-section structure; it applies in full to the 5 declared prose-output keys (s1.sizing_summarize, s8.business_case_prose, committee.position, company_profile.qualitative, company_profile.competitive) and to human-readable narrative fields of the 34 JSON-contract keys, so 39 of 40 keys carry the requirement with `pm.query_classify` the sole full exemption (router-internal, never human-rendered). (3) Boundaries unchanged: JSON output contracts stay byte-compatible (§5.5), Korean response pinning (i18n-design §4) unchanged, proposal-only disclaimers unchanged. Recorded in the two Row 0 files only — no code, no other docs.
