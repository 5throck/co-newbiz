## Context

- Defect: opportunity `01M7YXJ1062AVM5AXRZMBN41J2` ("TEST Pre-FS verify (delete me)") was
  delete-marked through `DELETE /api/opportunities/[id]` at 2026-11-21T12:56:53Z, but its
  latest `pre_fs` HOLD gate decision (01M7Z2D3J5V517T1F9NWHK1KT6, decided 12:48:22Z) kept the
  tombstoned deal visible in `GET /api/portfolio/pipeline` → `currentHolds` — the field that
  feeds the /deals board card badges/HOLD filter, the dashboard HOLD KPI, AND the inbox
  `gate_hold` items (`app/web-next/lib/inbox.ts:238-254`, built from
  `src.pipeline?.currentHolds`). A deleted deal must not count as a live portfolio hold on
  any of these three surfaces.
- Root cause verified in the working tree: the gate-aging query left-joins `md_project` and
  applies the ADR-0135-era tombstone/status predicate to project rows only
  (`app/web-next/lib/gate-aging.ts:43` — now 41-47 after the fix). Opportunity rows
  short-circuit the first disjunct (`g.entity_type != 'project'`) and bypass every deletion
  check.
- The DELETE endpoint behavior was re-verified against the route source: it delete-marks the
  unpromoted opportunity and writes a `deal_archive` manifest inside one transaction
  (`app/web-next/app/api/opportunities/[id]/route.ts:250-269` — transaction opens at 250,
  `UPDATE opportunity SET deleted_at ...` at 251, `recordDealArchive` kind='deleted' at 257,
  transaction closes at 269), which the EN playbook's API table omitted (the KO counterpart
  already stated the manifest write) — documentation rows are synced as part of this change.
- The tombstone column is `opportunity.deleted_at`, introduced by `db/migrations/0081_deletion_marks.sql:22`
  (the migration-0081 deletion-mark convention). Direct SQL replay of the new predicate
  against the dev DB (`db/data/co-newbiz.sqlite`) returned 0 rows for the fixture, whose
  `deal_archive` row 01M7Z2WPV1A5N7J22VD2HB0XWD is present.
- Consumer sweep 2026-11-21: `listGateAging` (the only query changed) is imported by exactly
  one production path — `app/web-next/app/api/portfolio/pipeline/route.ts:39` — plus three
  test files (gate-aging-track.test.ts, route-decision-current-authority.test.ts,
  adr-0104.test.ts, all pinning live-entity behavior and therefore unaffected); the pipeline
  response then fans out to the three feeds above (board badges/HOLD filter, dashboard HOLD
  KPI, inbox gate_hold items). `killEvalStates` and `listProjectPipeline` are separate
  queries in the same lib and are untouched by the predicate; no mcp/, scripts/, or db/
  imports exist.
- PM ruled the change EXEMPT under E3 (trivial fix: single predicate extension + focused unit
  tests + one documentation table row), user-approved this session; this record files the
  ruling first, per ADR-0061, before any code edit.

## Determination

1. **Row 0: EXEMPT under E3.** The change is a one-predicate data-correctness fix plus tests
   and two doc rows — no architectural seam moves, no contract change, no new surface.
2. **Predicate extension, symmetric to the project clause.** The query gains
   `LEFT JOIN opportunity o ON o.id = g.entity_id AND g.entity_type = 'opportunity'` and the
   WHERE gains `AND (g.entity_type != 'opportunity' OR o.deleted_at IS NULL)`. Because the
   join is conditioned on entity_type, project rows keep their current behavior exactly.
3. **Scope fence.** Opportunity `status='dropped'` rows are NOT excluded by this change —
   that is a separate semantics decision, not part of the tombstone defect.
4. **Verification obligations.** Focused unit tests (tombstoned opportunity excluded; live
   opportunity regression guard; project tombstone behavior unchanged), the existing
   gate-aging/portfolio test families green, and a live `GET /api/portfolio/pipeline` check
   through the running dev server confirming the fixture leaves `currentHolds`.
