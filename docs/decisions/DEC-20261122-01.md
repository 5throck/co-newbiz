  `authenticate` + `requireBusinessActor(auth.auth, "read")` — i.e. the read gate is authentication

  deal-data visibility); no project-membership, wall_group, or MNPI filter applies, because

  single-enforcement-point rule as "for project-membership filtering (FR-SEC-03)". The reviewer's
  claim therefore holds **with one refinement**: the class is every authenticated *business actor*

## Determination

1. **Amend, not revert.** ADR-0070's boundary is amended to carve one enumerated, read-only,
   session-gated, SQL-identical class of page-layer data access: the five carrier flat-route pages
   over the pre-project opportunity registry. The amendment does not touch ADR-0070 Decision 1 for
   any write path, any project-scoped read, or any data class not enumerated here; Server Actions
   remain prohibited absolutely (lint Rule 1 unchanged).
2. **Gate placement confirmed: scripts/co-newbiz/audit-variant.ts, blocking, ALLOWLIST mode.** The
   gate must enforce, in lint-server-boundary.ts driven by the hook:
   - Rule 1 (a `"use server"` file importing data access) — violation, absolute, no allowlist.
   - Rule 2 (data-access import in app/web-next/app/** outside app/api/**) — a violation unless the
     file is in `SANCTIONED_PAGE_ALLOWLIST` (exactly: app/market/page.tsx,
     app/opportunities/page.tsx, app/synergy/page.tsx, app/greenfield/page.tsx,
     app/brownfield/page.tsx) AND every data-access import in it belongs to the frozen module set
     {`db/client.ts` (getDb), `lib/carrier-resolve.ts`, `lib/rsc-session.ts`} — any `db/lib/**`,
     `db/repositories/**`, or `@prisma/client` import in an allowlisted page is a violation — AND
     the file contains no write-SQL shape (`INSERT INTO`, `UPDATE `, `DELETE FROM`, `PRAGMA`,
     `ATTACH`). Growing the allowlist or the module set requires a recorded DEC; removal is the
     revert path. The hook runs the lint as a subprocess and fails on non-zero exit (the
     route-audit-scan pattern).
3. **Compensating requirements binding the sanction** (implementation dispatch must satisfy CR-1
   and CR-5's doc corrections; CR-2..CR-4 are verified properties that must not regress):
   - **CR-1 — Role parity (NOT currently satisfied; must fix).** The page layer must not serve rows
     to a role the API would deny. Verified drift: `planCarrierPage`
     (app/web-next/lib/carrier-resolve.ts:130) resolves for ANY valid session, while all three
     carrier APIs return `role_forbidden` for admin (`requireBusinessActor(auth.auth, "read")`,
     FR-SEC-02). Fix: skip server-side resolution for admin sessions (rows=null → the client
     fallback hits the API and receives the same denial as before #862). This restores pre-#862
     effective visibility exactly; no other role is affected (viewer/analyst read access is
     identical on both paths).
   - **CR-2 — Session gating (verified; must hold).** Page-layer reads run only behind
     `getRscSession()`/`validateSession` — the same session store and lifecycle as Route-Handler
     auth; no parallel authentication logic may appear at the page layer.
   - **CR-3 — SQL parity (verified today; must hold and be pinned).** `resolveCarriers` must remain
     predicate-identical to the API queries it mirrors (opportunities GET under
     `?status=selected&includePromoted=1`; greenfield/brownfield GETs). Pin with a unit test at
     implementation so predicate drift fails CI rather than diverging silently.
   - **CR-4 — Read-only page layer (verified today; mechanically enforced going forward).** No
     write path may exist at the page layer — enforced by the gate's module-set freeze and
     write-SQL shape scan, and by the fact that the write/audit engine (db/lib/access-control.ts,
     repositories) is outside the frozen module set.
   - **CR-5 — Registry truth.** The implementation dispatch corrects the stale claims so the
     registry matches the re-homed gate: ADR-0070:3 (CI-wired wording → audit-variant.ts hook,
     noting the 2026-08-29 loss and this amendment) and SCRIPTS.md:95 (lint-server-boundary row →
     wired via co-newbiz/audit-variant.ts, allowlist mode per this DEC).
   - **CR-6 — Review trigger.** The sanctioned class is the opportunity registry AS GATED TODAY:
     no classification, mnpi_flag, wall_group, or read-audit semantics exist on opportunity rows,
     and page and API paths are symmetric in not logging reads. If sensitivity semantics ever
     extend to the opportunity registry (the F-11 share-link class of finding), this amendment is
     reopened — until then any filter added to one path must land in the other in the same change.
4. **Verification obligations for the dispatch.** `bun scripts/co-newbiz/lint-server-boundary.ts`
   exits 0 on the live tree under allowlist mode; `bun scripts/co-newbiz/audit-variant.ts` includes
   the new check as blocking and passes; a synthetic 6th page-level data-access import, a
   `db/lib/*` import in an allowlisted page, a write-SQL shape in an allowlisted page, and a
   synthetic `"use server"` + data-access file each fail the hook; the admin-session page visit
   renders the picker without server rows (CR-1 re-test); existing unit suites stay green.
