## Overview

co-newbiz is an AI-agent team and system that owns and operates the policies, procedures, guidelines, and checklists for new-business review — **Green Field** (new establishment) and **Brown Field** (M&A, including R&BD as a Brown Field subtype) — and implements that governance as a working review system, rather than a static document set.

Two axes are co-equal, per the design's own framing: **(A) governance ownership and operation** (authoring/amending policies, procedures, guidelines, checklists, and running their standing operation — compliance monitoring, waivers, interpretation registry, KPIs) and **(B) system build and maintenance** (implementing A as a system and keeping it running). A third axis, **(C) deal review**, runs real reviews on top of A and B and is the quality check on both.

Distinctive to the domain: many target industries have no direct market data, so demand is estimated through a proxy chain across upstream industries (e.g. crankshaft → marine engine → ship, with CGT/BHP/ton unit conversion). Chain reliability caps the confidence of every downstream conclusion — this is the RAG framework's data-confidence cap rule (see `docs/governance/rag-framework.md`).

**Tech stack**: SQLite (`bun:sqlite` access layer retained; Prisma + `@prisma/adapter-better-sqlite3` for schema/typegen) · Next.js (App Router, Route Handlers) + Prisma + Tailwind CSS + ECharts (ADR-0087 token-driven chart theme) — the web app lives in `app/web-next`, superseding the original Hono + React/Vite + ECharts stack per ADR-0069/0070 (accepted 2026-08-26); production runs as a Docker container with image CI/CD (2026-09-21, dev port 7749) and the UI is localized via next-intl ko/en catalogs (ADR-0184, 2026-10-23) · Python (python-docx / reportlab / python-hwpx) for document rendering · MCP server REST-proxied — one shared tool registry serves both stdio and the remote `/api/mcp` transport with OAuth 2.1 (ADR-0154, 2026-10-08) · TypeScript CLI (`bun scripts/co-newbiz/newbiz.ts`).

## Agents

**41 agents** across four co-equal domains plus `_core` and `_shared`, coordinated by PM acting as New Business Review Lead. Domain leads are design/review owners, not dispatchers — the workspace flat PM Gateway is preserved in full (PM is the only agent users invoke directly; all 40 specialists require PM dispatch).

| Domain | Count | Lead | Concern |
|---|---|---|---|
| `_core` | 1 | `pm` | Coordinates the four domain leads, enforces stage gates, approves ADRs |
| functional | 25 | `process-governance-manager` | Regulations, procedures, operation; review methodology; deal review (governance, analysis, greenfield, brownfield, dd, certification, partnership, group subdomains) |
| technical | 11 | `platform-lead` | System build and run — DB, API, UI, design system, deploy, ops, security |
| industry | 1 | `industry-lead` | Industry-specific characteristics, owned via `industry-profiles/*.yaml` |
| region | 1 | `region-lead` | Regional characteristics incl. domestic, owned via `region-profiles/*.yaml` |

Full roster with per-agent tier and role: `AGENTS.md`. Full definitions: `agents/*.md`.

**Three-stage review** applies to every deliverable: AI 1st (formal/completeness) → AI 2nd (cross-domain — must come from a different domain than the author) → human final (judgement and approval). Regulations, gate approvals, investment decisions, the security/privacy model, and ADRs cannot pass on AI review alone.

## Domain Configuration

- **RAG signal system** (`docs/governance/rag-framework.md`): six dimensions (financial, market, data confidence, regulatory/permit, technical/execution, risk) plus overall, rule-based (not weighted-average) — a Kill Criteria trigger or any assessed Red dimension forces overall Red immediately; an incomplete assessment (fewer than six dimensions genuinely assessed, none Red) yields no overall grade rather than defaulting to a color (Wave 5.10 defect fix, see `docs/pilots/pilot-001-system-rerun.md`).
- **Stage gates** (`process/flow.spec.yaml` v2.19.0 (ADR-0193 kill-criteria stage scoping; ADR-0192 S3 fit predicate), SSOT per ADR-0074): twelve business stages S1–S12 on one linear chain with track branching — greenfield runs S5 자체 진출 → S8 (S6 대상 후보 발굴 / S7 대상 선정 skipped via `applicableTracks`), brownfield runs S6 → S7 → S8 (S5 skipped); the common chain is S1 시장분석 → S2 기회 발굴 → S3 시너지·전략적 적합성 → S4 진출방식 결정 → … → S8 사업성 분석 → S9 실사·검증 → S10 투자구조 설계 (four-axis deal structure + sources & uses) → S11 투자심사·실행 → S12 사후 관리. The human-only gate ladder is screening → pre_fs → target_screening → fs → dd → entity_ic → group_ic — every verdict is a human decision (ADR-0053/0094), and Entity IC approval precedes Group-level procedure entry (`approval_chain`, ADR-0028). S2's entry-market sizing (진입시장 산정, ADR-0180/0181) fixes the basis market every later stage S3–S12 analyzes. Gate-ladder phases (0 intake → … → 7 finalization/QA) remain defined in `docs/phase-definitions.md` and referenced by the skill graph's `phase` edges (ADR-0073).
- **Runtime governance** (ADR-0183, 2026-10-24): every runtime LLM call passes a mandatory PM gateway backed by a PM activity catalog; the `/flows` console renders the S1–S12 flow with a session-scoped dry-run lane; AI suggestions stay proposal-only with human confirmation.
- **Governance layers** (`docs/governance/governance-operations.md`): Policy / Procedure / Guideline / Checklist / Template, each with distinct enforceability and revision authority — see the document-layer table in the design.
- **Procedure inheritance**: `procedures/{_shared,entities/<company>,regions/<ISO2>,group}/<proc>/schema.yaml` — entity/region procedures reference shared procedures via `references:` + `overrides:`, never copy them (ADR-0020); copies are audit-detected and blocked.
- **Information protection** (`docs/security/security-model.md`): project-membership access control (deny-by-default), minimal-collection/aggregate-only handling of personal data (executive compensation, comp benchmarks), and MNPI insider-list/access-log handling for listed-company deals — none of this is deferrable to a later phase (ADR-0038/0039/0040).
- **Investment vehicle structuring** (ADR-0045, `skills/investment-vehicle-structuring/`): tax structure, liability isolation, financing leverage, and exit structure are mandatory Pre-FS deal-structure-hypothesis axes for both Brown Field and Green Field, enforced via `checklists/brownfield-feasibility-checklist.yaml` bf-12 / `checklists/greenfield-feasibility-checklist.yaml` gf-11.
- **Remaining known gaps**: the working backlog index is now `docs/planning/product-backlog-roadmap.md` (approved 2026-09-09; it explicitly supersedes this file's former still-open list — consult its execution-status header for the current state). Disposition of the items this file listed on 2026-08-21 (sources: CHANGELOG 2026-09-09 waves A–E and the sim-engine line, `docs/architecture/mcp-integration.md`): **landed** — the 24-table DB migration gap (closed via migration 0011; all 68 documented tables migrate) with the Wave 5.7B REST/MCP parity surface over them; run versioning (engine-1: `db/lib/versioning.ts`, `model`/`diff` CLI, `compare_runs`) and the Monte Carlo REST surface (engine-2: `run_simulation`); all nine then-undeveloped `newbiz.ts` CLI commands (2026-09-09 Wave A — `fetch`/`md:sync`, `calibrate`/`convert`, `policy:sync`/`policy:impact`/`fin:project`; `law:sync` absorbed by the A1 law adapter, `export` covered by `db:export`); the two client-gated provenance gaps (2026-09-09 Wave D — `notification.read_at` read/unread with unread badge, project-list freshness signal, plus DD-tailor Tavily provenance); the empty `industry-profiles/` (13 KSIC-anchored, cited profiles — backlog Wave E); `hwp-document-processing`'s extraction path and the WACC input session (2026-09-09 engine seams, followed by the standalone simulation engine, ADR-0142); project closure/archival (Wave B1, 2026-09-09). **Still open** — the MCP-deferred engine tools (`get_financial_analysis`, `get_peer_benchmark`, `get_projection`, `get_proxy_chain`, `calibrate_chain`✱, `get_customer_risk`, `get_compensation_gap`, `run_model`✱, `generate_report`✱, `export_report`) await the CLI-backed async job surface (`docs/architecture/mcp-integration.md`); 14 of the 105 `skills/` directories are unregistered in `skills/SKILLS.md`.
