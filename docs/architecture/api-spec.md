## 1. Design Rules (Non-Negotiable)

- **Every endpoint enforces `project_member` filtering at the repository layer** (FR-SEC-01/03) — there is no endpoint that bypasses it, including admin-scoped ones.
- **Session cookie (web) + Bearer API token (MCP/CLI)** — tokens are stored hashed, scope-limited, never logged in plaintext.
- **MCP calls this API exclusively** (ADR-0011) — no separate code path with looser enforcement.
- **`mnpi_flag=true` projects are excluded from default list/search responses** across every endpoint below, not just MCP (FR-SEC-06/SYS-02).
- **`admin` is system-administration only (ADR-0146).** Outside the admin console (§8), business routes — `opportunities/**`, `brownfield/**`, `greenfield/**`, `companies/**`, `market-overview/**`, `synergy/**`, `our-company/**`, `archive/deals/**`, `projects/**`, `comments` POST, `agents/query` — reject admin with 403 `role_forbidden` on both reads and writes, via `requireBusinessActor(auth, mode)` in `app/web-next/lib/auth.ts`. Viewer writes keep 403 `role_required`. Exempt (open to admin as shared reference or self-service data): `glossary`, `notifications`, `auth/*`, `health`, `tokens` (read-only scope for admin — write-scoped issuance → 403 `role_forbidden`), `industries`, `benchmarks`, `series`, `procedures/resolve`, `llm-status`, `users/lookup`, `agents/registry`, `interpretations`, `data-changes`, `library`/`library/:docId`, `market-overview/ksic`, `market-overview/value-chain-graph`. `share/:token` is a public unauthenticated token route (ADR-0123) outside the role model. Wherever a row below says `analyst`+ or Authenticated for a business route, admin is excluded.
- **Write endpoints are audit-logged**, including the actor, scope, and diff where applicable (append-only `audit_log`, FR-SEC-07).

## 9. Response Envelope and Error Contract

```json
{
  "data": { ... },
  "meta": { "as_of": "...", "run_id": "...", "policy_version": "..." },
  "error": null
}
```

Every numeric figure in `data` that traces to an `assumption` carries its `assumption_key`, `as_of`, `source`, and `anchor_ref` in `meta` — this is the API-level realization of FR-SYS-03 (UI source tooltips read directly from this envelope, no separate lookup).

**Enforcement (ADR-0109):** the envelope is guaranteed on the error path by the `route()` wrapper in `app/web-next/lib/route.ts` — every API route handler is exported as `route(async ...)`, so an uncaught exception is converted into `fail(500, "internal_error", <message>)` in this same envelope instead of Next.js's default HTML 500, which JSON clients (`lib/api.ts`, the MCP REST layer) cannot parse. Handler-returned `Response`s (401/403/404/409) pass through untouched; the wrapper only covers what escapes.

Landing state: `ok()` carries provenance fields into `meta` via `envelope.ts`'s `provenance()` normalizer (`assumption_key`/`source`/`anchor_ref`/`run_id`; null/blank values are dropped so absent stays absent), attached **only where a route derives them from the rows it returns**: `GET /api/series/:id/observations` sets `source` when every returned row shares one `source_id`, and `POST /api/projects/:id/dd-findings` links the finding's `assumption_key` to the latest assumption-registry row for that key (`run_id`, `anchor_ref`). A multi-row response whose rows carry differing provenance keeps it per-row — the rows already carry their own columns — and never collapses it into one fabricated meta entry.

## 10. Rate Limiting and Abuse Prevention

- MCP write-scoped tools (marked ✱ in design §4-11) are rate-limited per token, independent of the web session limits.
- `safeFetch()` (FR-DATA-06) applies to any endpoint that triggers an outbound fetch (e.g. `watch:run`-adjacent manual-trigger endpoints), preventing SSRF via a crafted `source` override.

> ADR-0172 amendment 2026-10-15 (4): company profile evidence provided by an analyst. `POST /api/our-company/members/:memberId/analyze` (and `/api/companies/:companyId/analyze`) accept an optional body `{ sourceUrls?: string[] (max 8, http/https, ports 80/443 only), companyNote?: string (max 2000) }`; bad input returns 400 `invalid_source_urls` (naming the entries) / `too_many_source_urls` / `company_note_too_long`. The URLs, their per-URL fetch status (`ok` | `thin` | `failed`, char count, reason) and the note are **persisted** with the profile version (`dataSources.userSources`, `dataSources.analystNote`, `userNote`); fetched bodies are never stored or logged and the job-start audit entry records the URL count only. Fetching goes through `lib/safe-fetch-text.ts` (private/loopback/link-local/metadata IPs blocked, DNS re-checked on every hop, max 3 redirects, 10 s, 1.5 MB, text content types, 12k chars per URL / 40k total) and the text is passed to the model as fenced untrusted data with `[U<n>]`/`[N]` citation ids. New routes (same permission as starting a profile job, new version each time, audited under the calling user): `POST .../profile/sources` (add a hand-entered source: optional URL, title, excerpt up to 4000 chars; max 8), `PATCH|DELETE .../profile/sources/:sourceId` (hand-entered entries only; 403 otherwise; removal is soft so `[U<n>]` numbers never shift), `POST .../profile/overrides` (edit 산업 노출 / 강점 / 약점 / 사업 평가 with a required reason; edited items become `confirmed` in the verification ledger). Member routes only for the manual-source and override endpoints. Not exercised with a real network or LLM.
