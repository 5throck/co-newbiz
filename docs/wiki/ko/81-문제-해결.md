# 문제 해결: 증상에서 원인과 할 일 찾기

**목적:** 화면에서 막혔을 때 증상으로 찾아 원인과 할 일을 확인한다. 원하는 답이 없으면 [80-자주-묻는-질문](80-자주-묻는-질문.md)을 본다.

**누가/언제:** 모든 사용자, 막혔을 때.

**사전 조건:** 없음.

> [!NOTE]
> 이 쪽이 설명하는 화면은 [12-공통-화면-둘러보기](12-공통-화면-둘러보기.md)와 단계 안내의 **데모 자료** 화면에서 확인했다. 내 자료의 이름과 숫자는 다를 수 있다. 내 화면에서 해결되지 않으면 프로젝트 리드나 운영자에게 알린다.

## 증상별 목록

### 다음 단계가 열리지 않아요

| 확인 | 원인 | 할 일 |
|---|---|---|
| 번호 띠 칸이 `승격 후`로 보임 | 기회(S1~S7)가 아직 프로젝트(S8~S12)로 승격되지 않았다 | 앞 단계를 끝내고 대상 선정·승격을 마친다 |
| 안건 개요 `완료 조건`에 빈 항목 | 필수 산출물이 없다 | 해당 단계 화면에서 산출물을 입력한다 |
| 단계 화면에 `이 단계 완료 요건 충족` 초록 줄이 없음 | 완료 조건이 아직 충족되지 않았다 | `3단계 검토`의 `확인하지 못함`, `판단 필요`를 읽고 부족한 기록을 채운다 |
| 요건은 충족인데 다음 단계가 잠김 | 게이트 결정이 아직 없다 | 안건 개요의 `다음 할 일` 버튼(예: **타당성 분석(FS) 결정 열기 →**)으로 사람이 게이트 결정을 기록한다 |
| 프로세스 현황에 `미적용` 표지 | 이 트랙에서 쓰지 않는 단계다(예: 브라운필드의 S5, 그린필드의 S6·S7) | 오류가 아니다. 트랙 쪽 단계로 간다 |
| **결정**·**결정 기록 (사람)** 버튼이 안 눌림 | 결정 권한이 없는 역할이거나 입력이 덜 채워졌다 | 필수(`*`) 칸을 모두 채우고 내 역할이 리드·검토자인지 확인한다([02-역할과-권한](02-역할과-권한.md)) |

### 범위를 바꾼 뒤 S9 실사가 완료되지 않아요

1. **증상:** 어제는 S9 완료였는데 오늘은 `판정 완료 · 필수 미충족 0건`이 사라지고 미판정 항목이 늘었다.
2. **원인:** 실사 범위가 바뀌면(대상 변경, 선택 항목 추가, 범위 적용 날짜 기준 변경) 새로 범위에 들어온 항목이 아직 판정되지 않은 상태가 된다. 이미 입력한 판정은 지워지지 않는다. 게이트 `DD` 결정이 이미 기록된 프로젝트는 그 시점의 범위가 고정된다.
3. **할 일:** S9 분야 탭에서 `보기`의 `판정 대기만`으로 좁혀 새 항목을 판정한다. 필요 없는 항목은 **해당없음**이나 **면제 요청·연결**로 처리한다. 범위를 사람이 정하는 화면은 [53-브라운필드-S9-실사](53-브라운필드-S9-실사.md)와 [42-그린필드-S9-실사](42-그린필드-S9-실사.md)다.

### 단계(작업)를 완료할 수 없어요

| 증상 | 원인 | 할 일 |
|---|---|---|
| 설립 실행 단계를 `완료`로 못 바꿈 | 증적(근거 자료)이 없거나 앞 단계가 안 끝났다. 담당자 구성원 검증도 필요하다 | 근거를 첨부하고 순서를 지킨다. 완료 처리는 사람만 한다 |
| 이미 끝낸 단계를 고쳐야 함 | 완료한 단계는 직접 고칠 수 없다 | 단계의 **완료 취소(재개)** 를 쓴다. 사유가 필요하고 증적은 이력에 남는다. 완료확인(5단계)이 완료 상태면 함께 재개한다 |
| 투자 분할 집행을 `집행 완료`로 못 바꿈 | 집행은 두 사람이 필요하다(요청 한 사람, 승인 다른 한 사람) | 다른 사람이 요청한 건을 승인한다. 집행 완료로 기록되면 되돌릴 수 없다 |
| 게이트 `HOLD` 결정이 기록되지 않음 | HOLD는 미완료 산출물 목록 없이 기록할 수 없다 | 미완료 산출물을 적고 다시 시도한다 |
| `결정`이 눌리지 않고 "근거를 입력하면 결정을 기록할 수 있습니다" | `근거 *`가 비어 있다 | 근거를 쓴다 |

### GO가 기록되지 않아요 (게이트 무결성)

| 증상(화면 문구) | 원인 | 할 일 |
|---|---|---|
| `GO에는 항목별 확인(사유 포함)이 필요합니다` 또는 항목 옆 `이 항목의 사유를 입력해 주세요.` | 확인할 항목(중단 조건, 적색·없는 등급, 끝나지 않은 필수 항목)에 사유가 없다 | `GO를 기록하기 전에 확인할 항목` 목록의 항목마다 사유를 쓴다 |
| `검토한 이후 게이트 상태가 바뀌었습니다. …다시 확인해 주세요.` | 상자를 연 뒤 상태가 바뀌었다 | 새로 생긴 항목을 읽고 사유를 더한 뒤 다시 누른다. 이미 쓴 사유는 남아 있다 |
| `근거가 너무 간단해 기록할 수 없습니다.` | 근거가 자리표시자이거나 너무 짧다 | 판단의 실제 이유를 직접 쓴다 |
| `AI 브리프는 다른 결론을 권고했습니다. 다르게 결정하는 이유를 직접 적어 주세요.` | GO가 저장된 AI 권고와 다르다 | `AI 권고(…)와 결정이 다른 이유는 무엇입니까?` 칸에 이유를 쓴다 |
| `필수 M&A 검증이 기록되지 않아 GO를 기록할 수 없습니다` | 브라운필드 여섯 검증 중 빠진 것이 있다 | 목록에 나온 검증을 기록한다. 면제 방법은 없다 |
| `할인율이 확정되지 않아 GO를 기록할 수 없습니다` | 적용 주체, WACC, 허들 IRR을 사람이 확정하지 않았다 | S8 `WACC` 탭에서 확정한다. 면제 방법은 없다 |
| `인증 확인이 안 되어 GO를 기록할 수 없습니다` | 핵심 인증의 인수 후 이전 가능성을 인증기관 규정으로 확인하지 못했다 | 인증기관 자체 규정으로 확인한 결과를 기록한다 |
| `중단 조건 때문에 GO를 기록할 수 없습니다` | 발동한 중단 조건에 그룹 투자심의위원회의 예외가 없다 | 그룹 투자심의위원회 검토자에게 `중단 조건 예외`를 받거나 HOLD·KILL을 기록한다 |
| `열린 조건이 있어 GO를 기록할 수 없습니다` | 그룹 심의 전에 풀어야 할 조건이 열려 있다 | 조건을 해소(메모, 필요하면 근거 자료)한다 |
| `앞 단계 게이트에 유효한 GO가 아직 없습니다.` | 앞 게이트가 없거나 두 번째 검토를 기다린다 | 앞 게이트부터 기록하고 두 번째 검토를 마친다 |
| `승인하는 검토자는 결정을 기록한 사람과 달라야 합니다.` | 직접 기록한 GO를 스스로 확인하려 했다 | 다른 검토자에게 맡긴다 |
| `관리자가 부여하는 담당 역할 권한이 있어야 할 수 있는 작업입니다.` | 위원회 검토자 권한이 없다 | 관리자에게 권한을 요청한다 |
| `이 프로젝트는 새로 사용하기 전에 다시 확인해야 하는 이전 기록입니다 …` | 다시 확인 요건이 열려 있다 | 알림의 항목을 마치고 검토자가 요건을 해제하게 한다([60-프로젝트-화면-안내](60-프로젝트-화면-안내.md)) |

HOLD와 KILL은 위 어느 경우에도 기록할 수 있다. 시행 전 단계인 규칙은 막지 않고 `아직은 GO를 막지 않습니다`라고만 알려 준다.

### 차입·대출 화면에서 약정 조건 여유가 계산되지 않아요

1. **뜻:** `약정 조건 여유를 계산할 수 없습니다 …`는 값이 없어서 계산을 하지 않았다는 안내다. 화면은 값을 추정해서 채우지 않는다.
2. **원인:** 채택한 S8 케이스가 없다. 차입에 만기, 상환방식, 금리 중 빠진 것이 있다. 금리를 `0.05`처럼 소수로 썼다.
3. **할 일:** S8에서 케이스를 채택하고 차입을 `관리` 열에서 고쳐 빠진 칸을 채운다. 금리는 퍼센트 값(`5`)으로 쓴다. 자세한 읽는 법은 [54-브라운필드-S10-거래-구조](54-브라운필드-S10-거래-구조.md)를 본다.

### 왜 게이트 승인·완료·재개는 사람만 기록하나요

이 시스템은 의사결정 지원 도구다. AI는 초안, 근거, 제안 등급을 만들고 게이트 승인, 투자 결정, 진출방식 결정, 대상 선정, 단계 완료와 재개, 담당자 지정은 사람이 본인 계정으로 기록한다. 에이전트나 개인 API 토큰으로 이런 기록을 시도하면 서버가 `human_only`로 거절한다. 화면 문구도 "에이전트는 결정을 제안할 수만 있습니다"라고 알린다. 이유는 다음과 같다. 책임은 사람에게 남아야 하고 AI가 AI의 결과를 확인하면 같은 맹점을 공유해 오류가 걸러지지 않는다. 자세한 내용은 [02-역할과-권한](02-역할과-권한.md)을 본다.

### "AI 2차 검토는 수행되지 않았습니다"가 나와요

1. **뜻:** 단계 화면 `3단계 검토`에서 AI 2차(다른 영역 교차 검토)가 실행되지 않았다는 안내다. 아무 문제가 없다는 뜻도, 통과라는 뜻도 아니다. 침묵은 승인이 아니다.
2. **원인**(화면 위쪽 `AI 2차` 줄에 사유가 적힌다): AI 1차에서 미완료·잠김 단계 같은 빈틈이 발견되어 아직 교차 검토 단계가 아님, 외부 AI 설정이 없음, 월간 사용 한도 도달, 호출 실패, 검토 결과 형식 오류, 작성 에이전트의 영역이 겹쳐 다른 영역 검토자를 정하지 못함.
3. **할 일:** 사유를 읽고 해소한 뒤 **AI 2차 검토 요청**(이미 한 번 돌렸다면 **AI 2차 검토 다시 요청**)을 누른다. 이 버튼은 분석가 권한이 필요하다. 해소할 수 없는 사유(설정, 한도)는 운영자에게 알린다. 그동안 사람이 `확인하지 못함` 구역을 직접 보고 판단한다. 규정, 게이트 승인, 투자 결정은 AI 검토만으로 통과할 수 없다.

### 베타 회귀 자료가 불러와지지 않아요

WACC 화면의 베타(β) 계산에서 `수집 데이터 사용`으로 시계열을 불러오는 경우다.

| 화면 | 원인 | 할 일 |
|---|---|---|
| "수집 데이터를 불러오지 못했습니다." | 수집 자료를 읽는 중 오류 | **수집 데이터 불러오기**를 다시 누르고 계속되면 운영자에게 알린다 |
| 상태줄에 ⚠ 또는 ✕와 명령어가 보임 | 이 종목·지수 자료가 아직 수집되지 않았다 | 보이는 명령어 옆 **명령 복사**를 눌러 운영 담당에게 전달한다(명령을 실행할 수 있는 사람은 운영 환경에 따라 다르다) |
| `시계열 회귀에는 최소 약 3개월(거래일 63개) 데이터가 필요합니다 — 현재 N건` | 거래일 수가 모자라다 | 기간을 늘려 다시 수집하거나, `직접 붙여넣기` 탭에 `date,price,index`(날짜, 종가, 지수값) 한 줄씩 붙여 넣는다 |
| `정렬` 줄 "거래일 N일 / 최소 M일 ⚠ 부족" | 종목과 지수의 겹치는 거래일이 적다 | 위와 같다. `시장 지수` 드롭다운에서 짝 지수를 바꿔 볼 수도 있다(`— 수집 없음` 표시는 자료 없음) |
| **↻ 회귀 실행**이 비활성 | 행이 63개 미만이거나 자료가 비어 있다 | 위 자료 부족 원인을 먼저 해결한다 |

### "서버 응답이 비어 있거나 손상되었습니다"가 나와요

1. **증상:** 화면에 `서버 응답이 비어 있거나 손상되었습니다 — 잠시 후 다시 시도하세요.`가 뜨고 특정 화면(예: S9 `리스크 히트맵`, S10 `차입·여신`, S11 실행 기준선)의 자료만 계속 불러오지 못한다.
2. **원인:** 프로그램은 새것인데 데이터베이스 마이그레이션이 아직 적용되지 않은 상태다. 앱은 서버를 시작할 때만 마이그레이션을 자동 적용하므로, 오래 켜 둔 개발 서버는 새로 생긴 표·칸을 읽지 못해 실패한다. 서버는 `503 migration_pending` 응답과 함께 `데이터베이스 마이그레이션이 적용되지 않았습니다 — dev 서버를 재시작하거나 bun run db:migrate 를 실행하세요.` 안내를 돌려 준다.
3. **할 일:** 안내대로 개발 서버를 재시작하거나 `bun run db:migrate`를 실행한 뒤 화면을 다시 연다. 명령을 실행할 수 없는 사람은 이 문구를 운영자에게 그대로 전달한다.

### 로그인과 계정

| 증상 | 원인 | 할 일 |
|---|---|---|
| 로그인이 안 됨 | 계정 신청 뒤 관리자 승인 전 | 운영자에게 승인을 요청한다 |
| 임시 비밀번호로 들어왔는데 다른 화면이 안 열림 | 비밀번호를 바꿔야 한다 | `비밀번호 변경`에서 새 비밀번호(8자 이상)를 설정한다. 임시 비밀번호는 재사용 불가다 |
| 저장 버튼이 안 눌림 | 열람자(`viewer`) 역할 | 운영자나 프로젝트 리드에게 역할 변경을 요청한다 |
| 운영 모드에서 삭제가 안 됨 | 시스템 모드 보호 | 의도된 보호다. 운영자가 개발 모드로 바꿀 때만 가능하다([70-관리자-화면-안내](70-관리자-화면-안내.md)) |

### 화면이 비어 있거나 영어가 보여요

- `N/A`, `—`, `증거 부족`, `정책 미설정`, 빈 표는 자료가 아직 없다는 뜻인 경우가 많다. 오류로 보이는 영어 문구(`Failed to fetch`, `Business Case`, `base`, `p50` 등)는 알려진 화면 표기 문제다. 결함 기록에 올라 있으며 업무 판단에는 영향이 없다.
- 단계 화면을 여는 순간 `3단계 검토`를 만드는 기록이 서버에 남는다. 읽기 전용 계정에서는 `불러오지 못함`으로 보일 수 있다.
