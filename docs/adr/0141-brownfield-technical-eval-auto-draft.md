# ADR-0141 — S7 기술 평가 자동 초안(공시·프로파일·웹 근거 + "확인 안됨" 명시)

- Date: 2026-09-16
- Status: accepted (implemented same day)
- Builds on: ADR-0140 (재무 평가 자동 초안 — 같은 "초안만 만들고 저장은 사람" 패턴)

## Context

재무 평가에 이어 사용자 요청(2026-09-16): 기술 평가 항목(S3 역량 갭 레지스터에서
시딩, ADR-0139/0136)도 후보 회사의 최근 3년 공시 정보 등으로 확인 가능한 사안은
자동 초안으로 진행하고, 확인되지 않는 사안은 "확인 안됨"으로 명확히 제시해야
한다. 기술 역량 보유 여부는 재무와 달리 숫자 루브릭으로 판정할 수 없다 — 근거
텍스트(공시 제목, AI 프로파일, 웹 검색)의 해석이 필요하다. 이미
chk-target-screening 판정 초안(ADR-0118)이 "웹 근거 → LLM 초안 → 사람 확정,
근거 없으면 판정하지 않음" 패턴을 확립했다.

## Decision

1. **기술 평가 초안은 LLM+근거 기반으로 만든다**
   (`lib/brownfield-technical-draft.ts`). 근거 3종 — (a) 최근 3년 DART 공시
   제목(dart-client `searchDisclosures`에 선택적 `months` 파라미터 추가,
   기본 12개월은 기존 호출자 불변), (b) 회사 AI 프로파일(강점·약점·종합평가·
   산업 노출·경쟁 포지셔닝, `loadLatestProfile`), (c) 항목별 웹 검색
   (Tavily 설정 시). 시스템 프롬프트는 `s7.screening_draft`를 재사용한다
   (근거 기반 판정·추측 금지 원칙이 동일).
2. **"확인 안됨"은 정당한 출력이다.** LLM 프롬프트에 `unverified`를 명시적
   verdict로 요구하고, 근거 미달·LLM 미설정·파싱 실패로 초안이 없는 항목도
   모두 "확인 안됨" 사유와 함께 반환한다 — 빈 칸으로 남기거나 판정을
   지어내지 않는다. UI는 회색 "확인 안됨" 칩 + 사유 + 근거 노트(편집 가능,
   기본값 "확인 안됨(자동 진단) — 사유")로 표시해, 사람이 직접 판정할 때
   미확인 사실이 노트에 기록되게 한다.
3. **경계는 ADR-0140과 동일** — 초안은 저장되지 않는다. `POST eval-draft`에
   `category: "technical"` 분기를 추가해 같은 엔드포인트에서 처리하고, 확정은
   기존 `PUT eval-state`(assessed_by=사용자)로만. 이미 사람이 판정한 항목은
   초안 대상에서 제외. 감사 로그는 `target_eval.technical_draft`.
4. **근거 인용 규칙** — pass/partial/fail 제안에는 근거 한 줄(rationale)과
   웹 출처 URL(source_index 복원, 호스트명 배지)을 붙인다. 근거 요약
   ("공시 N건(3년) · AI 프로파일 · 웹 M건")을 항목별 배지로 표시해 사람이
   제안의 근거 강도를 한눈에 보게 한다.

## Alternatives considered

- **기술 평가도 결정론 루브릭으로** — 기각. 역량 보유 여부는 공시 제목
  키워드 매칭 같은 결정론으로 판정할 수 있는 성질이 아니며, 오탐이 "확인
  안됨"보다 해롭다.
- **공시 본문(사업보고서 PDF) 파싱까지 확장** — 기각. 본문 파싱은 신규
  통합(범위 확대). v1은 제목·프로파일·웹 스니펫으로 확인 가능한 것만
  판정하고 나머지는 확인 안됨으로 둔다.
- **"확인 안됨"을 별도 판정 상태(DB enum)로 추가** — 기각. 판정 값은
  사람 확정본만 기록한다(ADR-0139 스키마 불변). 미확인은 초안 표시·노트로
  충분하다.

## Consequences

- 기술 평가 카드에 "기술 판정 초안 (공시·프로파일·웹)" 버튼이 붙는다 —
  근거 수집(공시 2회 + 항목별 웹 검색 + LLM)에 수 초~수십 초 걸릴 수 있다.
- LLM·웹검색 미설정 환경에서는 모든 항목이 "확인 안됨 — LLM 미설정"으로
  돌아간다(설정 가이드 노트 표시). 공시 제목만으로는 확인 가능한 사안이
  제한적이다 — 근거 강도 배지로 그 한계를 투명하게 보여준다.
- 공시 제목 기반이므로 오탐 가능성은 사람 확인으로 걸러진다(초안 저장 전
  수정 가능). 본문 기반 고도화는 후속 범위.
