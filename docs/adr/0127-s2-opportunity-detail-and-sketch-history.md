# ADR-0127: S2 기회 상세 화면 분리 + 비즈니스 모델 검토 버전 이력

- Status: Accepted
- Date: 2026-09-13
- Deciders: PM (dispatch), backend-engineer (schema/API), frontend-engineer (S2 UI)
- Related: ADR-0094 (경계 #2), ADR-0014 (additive-only migration), ADR-0119
  (행당 대표 액션 원칙), baseline-v5 mockup (S2 섹션)

## Context

S2 기회 발굴 화면의 행 펼침 패널이 비대해졌다 — 요인 편집, S3 실행, 스케치,
매력도 평가, 승격 패널이 한 행 아래 펼쳐진다. 사용자 요청:
1. 기회 클릭 시 하단 펼침이 아니라 **상세 화면**으로 이동한다.
2. 행 버튼은 **선별·제외·비즈니스 모델 검토(구 스케치)·삭제**만 남긴다.
3. "스케치" 명칭을 **비즈니스 모델 검토**로 바꾼다.
4. S3 시너지·전략적 적합성은 인라인 실행이 아니라 **S3 화면(/synergy)으로
   이동**하는 링크가 바람직하다.
5. 재생성이 과거 검토를 덮어써 **이전에 분석한 비즈니스 모델 검토를 볼 수
   없다** — 이력 열람이 필요하다.
6. S1 가치사슬 연계에서 승인 대기 제안이 없을 때 실제로 링크를 등록할
   방법이 없다 — 수동 등록 UI가 필요하다.

## Decision

1. **새 상세 화면 `/opportunities/{id}`** — 기회 정보, 기회/위험 요인
   (조회·자동 도출·수동 추가/삭제), 매력도 평가(+LLM 초안), 비즈니스 모델
   검토(현재 + 버전 이력), 승격 패널(선별 상태)을 담는다. 목록의 기회명
   클릭은 이 화면으로 이동한다. S3 시너지·전략적 적합성은 인라인 실행
   버튼을 두지 않고 S3 화면(/synergy)으로 이동하는 링크로 대체한다 —
   시너지 분석은 계열사/그룹 단위 분석이므로 S3 담당 화면이 원래 장소다.
2. **행 버튼 축소**: 목록 행의 액션은 선별·제외(S3 완료 시 활성), 비즈니스
   모델 검토, 삭제만 남긴다(S8/S9/S11/S12 링크 제거 — 승격 후에는 프로젝트
   화면이 단일 진입점).
3. **명칭 변경**: "스케치"/"비즈니스 모델 스케치" → "비즈니스 모델 검토".
   API 경로(/sketch), 테이블(sketch_json) 등 기술 식별자는 유지.
4. **`opportunity_sketch_version` 테이블** (migration 0091, append-only) —
   검토 생성/재생성 때마다 버전을 쌓는다. opportunity.sketch_json은
   "현재 버전" 포인터 역할을 유지하고, 상세 화면에서 버전 이력 열람을
   제공한다.
5. **S1 가치사슬 연계 수동 등록**: 제안이 매칭되지 않아도 산업 마스터에서
   직접 선택해 structural hop으로 등록할 수 있는 폼을 둔다(ADR-0126
   엔드포인트 재사용 — 제안 승인과 같은 승인 행위다).

## Consequences

- 목록 행은 경량 퍼널로 유지되고 평가·검토 작업은 상세 화면에 집중된다.
- 과거 비즈니스 모델 검토가 보존되어 비교·추적이 가능하다(append-only).
- S3 실행이 S2에서 사라지므로, S3 완료 여부(시너지 점수·적합성 판정)는
  상세 화면에서 판정 결과 링크로 안내한다.
